先看全局

这些测试一起回答什么问题？

员工的请求要经过三段：员工的工具 → 我们的网关 → 上游供应商 KerAPI → 模型。任何一段出问题，员工都会遇到。所以每个测试只盯一个问题，合起来覆盖整条路。

所有对比测试共用一个思路：拿官方当尺子

同一个请求、同样的参数，一份直接发给模型官方（DeepSeek 官方、智谱官方），一份走我们的 API（和员工拿到的完全一样）。官方能做到的，我们也要做到；官方自己做不到的，是模型本身的边界，不算我们的问题。

推荐的节奏

什么时候做什么在哪里
一直在跑，不用操作Key 巡检（每 30 分钟）、上游日志对账（每 5 分钟）。有问题会发邮件。运行观测、计量核账
每周一次功能对比（常用项，约 1 分钟）；身份检测，高峰和低谷各一次验收测试 → 功能对比；对比评测 → 身份检测
新模型 / 新供应商上线前采购 Key 检测 → 任务验收 → 功能对比（全选）→ 身份检测（含小测）→ 型号对比 → 压测 → 发布按这个顺序，一步过了再做下一步
员工常用的 Agent 升级后Agent 检测重新回放；兼容性矩阵点“回放全部”验收测试 → Agent 检测 / 兼容性矩阵
每月计量核账看“有差异”和“证据不全”，和供应商账单总额对一下计量核账
收到告警或员工报错先看运行观测的事件；确认是上游问题，就在路由与熔断里暂停这个模型运行观测 → 路由与熔断
花钱有上限，失败不自动重试。每个测试开始前都会弹窗告诉你大约要调用多少次。测试题都是极短的人造题，不含员工的数据。

评测 Key

拿什么当尺子？

是什么：各厂商官方的 API Key。只用来做对比和检测，是所有“官方 vs 我们”测试的尺子。

怎么操作

  1. 打开 验收测试 → 评测 Key。
  2. 选厂商（DeepSeek 官方 / 智谱 GLM 国内 / Z.ai 国际），粘贴 Key，保存。
  3. 系统会向厂商查询这把 Key 能用哪些型号，并自动登记好。

需要知道的规则

  • 每家厂商只保留一把有效 Key；换新 Key 时旧的自动停用。
  • 它的类型是“参照”，路由只会选“供应商”类型，所以员工的请求不可能用到官方 Key。
  • 官方 Key 的余额和限流会影响测试。对比里官方那一列报“429 / 余额不足”，先给官方账户充值，不是我们的问题。

采购 Key 与 Key 检测

KerAPI 给我们的 Key 通不通？每个模型通不通？

在哪里：上游接入 → 采购 Key。每家供应商有一把主用 Key 和若干备用 Key；主用失败时，员工请求自动改用备用。

怎么操作

  1. 选供应商，填名称、API Key、接口地址，点 保存并检测。
  2. 看每个型号的点：绿色能用，红色会显示供应商的原始报错。型号按延迟从快到慢排。
  3. 想随时复查，在“运行观测”或上游页点 立即检查（和每 30 分钟的自动巡检是同一件事）。

看到这些提示时

提示意思怎么办
备用 Key 和主用是同一把两把 Key 的指纹一样，其实是同一把，主用失效时无处可切在 KerAPI 后台新建一把真正不同的 Key 登记进来
只有主用 Key主用失效时员工调用会中断再登记一把备用
不遵守输出上限要求最多 1 个 Token，上游却返回了很多不用处理：网关已自动启用“输出保护”（见第 13 节）
红点 401 / 403Key 无效、过期或没开通这个型号去 KerAPI 后台检查 Key 和型号权限

功能对比

官方能做的功能，我们这条线路也能做吗？

为什么要测：员工用的 Agent 依赖很多“功能”：工具调用、流式输出、JSON 输出、思考强度、长上下文……网关的限制或供应商对参数的改写，都可能让某个功能在我们这里失效。公网的实测报告页就来自这里。

25 项测试，8 类能力

类别测试在测什么
基础基础对话、流式输出能正常回答；流式能逐字返回并正常结束
工具调用工具调用、指定工具、工具结果回传、一次调用多个工具Agent 的核心能力
输入与格式图片输入、JSON 输出、JSON Schema、停止词多模态、结构化输出、stop 参数
思考思考 低 / 中 / 高 / 超高、开启 / 关闭思考思考强度和开关是否生效
输出长度输出 ≥8K、≥32K、截断标记长输出是否放行；超限时是否标记 length
长上下文≥32K、≥128K约 3 万字 / 12 万字输入（费用较高，默认不勾）
对话系统提示词、多轮记忆是否遵守 system；是否记得上一轮
计费流式返回用量、缓存命中计费依赖的 usage 和缓存是否回报

怎么操作

  1. 确认表头：第一行是我们卖给员工的产品，第二行是对照的官方型号（自动配好，一般不用改）。
  2. 勾选要跑的测试（左侧勾选框，或“常用 / 全选”），点右上 对比所选测试。常用项约 1 分钟。
  3. 跑完后点任意格子，右侧弹出两边的原始回答。

怎么看结果

符号意思要不要处理
✓ 一致官方能用，我们也能用不用
＋ 更多官方报错或不支持，我们能用（网关替模型做了换算）不用，是加分项
— 模型限制官方自己也不行，两边一样不用，是模型的边界
✕ 差异官方能、我们不能要修。点格子看是“网关拒绝”还是 KerAPI 报错
结果不会自己变。修好之后要重新对比一次，格子才会更新。结论不稳定的项（这次一致、下次差异）多跑两次再下结论。

对外发布

对比跑完、没有差异后，点 发布到实测报告，公网页面只显示每项的结论和简短说明，不公开回答原文。

Agent 检测

某个 Agent（如 WorkBuddy）真实发出的请求，我们接得住吗？

为什么要测：功能对比用的是标准请求，而真实的 Agent 会发出很特别的请求：几十个工具定义、超长系统提示词、少见的参数组合。只有拿它真实发出的请求来试，才知道员工用起来行不行。

怎么操作

  1. 选 Agent 和版本（没有就新建）。
  2. 第一步 · 拿到请求（左边）：已打勾的功能已经有了，来自员工真实调用或之前的录制。没打勾的，点 开始录这项，然后有人在 Agent 里用一次这个功能，录到后点停止。
  3. 第二步 · 回放（右边）：每行是我们的一个产品。勾“试”走我们的线路，勾“对照”同时发给官方。点 回放。

怎么看结果

  • ✓ 能用、! 部分能用、✕ 不能用。
  • 同一行官方 ✓、我们 ✕ = 我们的问题，要修。
  • 两边都 ✕ = 模型本身不支持，或这个 Agent 的设置本来就不对。
  • Agent 升级后版本号变了，要重新录、重新回放。
5

兼容性矩阵

哪个工具 × 哪个选项能用？

和 Agent 检测的区别：矩阵的数据是被动积累的：员工每用一次某个工具，网关就自动记下这个工具的请求格式。Agent 检测是工作人员主动按功能去录。

怎么操作

  1. 想让矩阵多出一个工具：在那个工具里填我们的地址和一把员工 Key，正常用一次。
  2. 想多测一个选项（如思考强度“高”）：在工具里打开这个选项，再发一句话，矩阵里会多出一个“见过 · 未回放”的格子。
  3. 回到这页，选模型，点 用所选模型回放全部，或点单条的 只回放这条。

怎么看结果

  • 绿色 ✓：回放成功。
  • 灰色“见过 · 未回放”：员工用过，还没测。
  • 红色角标“网关拒绝 N 次”：员工真实调用时就被我们的网关拒绝了，通常是参数超出上限，要改网关或在文档里提醒员工。

任务验收

新接入的型号，能不能正确答题、用量报得对不对？

题目内容通过条件

怎么操作

  1. 打开 验收测试 → 任务验收，选待测型号，点 启动真实测试。
  2. 页面上方出现“最近一批”进度框，每道题的输出、Token 和延迟实时显示。
  3. 跑完后可以点 导出核对 CSV。

逐笔交易

身份检测（新）

供应商给的，真的是官方那个模型吗？是满血版吗？

为什么要测：中转行业最常见的问题是“挂羊头卖狗肉”：名字叫 GLM-5.3，背后其实是更便宜的模型，或者是量化、缩小过的版本。功能对比看不出来，因为便宜模型也能调工具、也能输出 JSON。身份检测专门回答“是不是同一个模型”。

四项检测分别看什么

① 分词指纹 · 最可靠

5 段固定文字（中文、英文、代码、数字符号、生僻字和表情），两边各算输入 Token 数。不同模型家族的分词器不一样，同一段文字算出的数一定不同。

② 自报身份 · 旁证

问“你是什么模型？哪家公司开发的？”，看是不是自称同一家；同时看响应里回报的型号名。模型常会说错（DeepSeek 连官方 API 都常自称 ChatGPT），所以只作旁证：分词已经一致时，自称别家不作数。

③ 输出相似 · 参考

温度 0，三道开放题。先让官方答两次，看官方自己两次有多像（基准）；再看我们和官方有多像。我们明显低于基准，说明说话风格不一样。

④ 能力小测 · 抓降级

20 道只有一个正确答案的题，规则判分。量化或缩小过的模型，在多位数计算、日期推算、代码输出这类题上更容易错。

怎么操作

  1. 打开 对比评测 → 身份检测。
  2. 勾选检测项：身份指纹（每个型号 21 次调用，约 1 分钟，几分钱）；能力小测（每个型号 40 次调用，需要思考，约 5～15 分钟，几元钱）。
  3. 点 开始检测，确认弹窗。检测中进度条实时更新，可以离开页面。
  4. 跑完看每个型号的卡片，点卡片看明细：分词对照表、两边的自我介绍、相似度、每道题两边的答案。
  5. 高峰（工作日 9–18 点）和低谷各测一次，在“历史”里比较。有的供应商会在高峰期悄悄切到便宜模型。

怎么看结果

结论什么情况下出现怎么办
正常分词一致，自称同一家，小测和官方持平不用处理
需要关注分词固定多几个 Token；或小测少对 2 题；或回答风格和官方差得多；或思考长度差一倍以上；或分词不一致时还自称别家换个时段再测一次；固定多 Token 要问供应商是否加了系统提示词（这部分我们会多付钱）
疑似不是同一个分词差值忽大忽小；或小测明显低于官方截图明细发给供应商要求解释；必要时在“路由与熔断”暂停该模型
局限：同一家公司的大小模型（如 GLM-5.3 和 GLM-5.3-Flash）可能共用一个分词器，分词指纹分不出来，要靠能力小测和型号对比。小测只有 20 道题，单次少对 1～2 题属于正常波动，所以要看多次的趋势。

型号对比

供应商的回答质量，和官方一样好吗？

和身份检测的区别：身份检测问“是不是同一个模型”，用的是短题和硬指标；型号对比问“回答好不好”，题目更开放（写 SQL、写客户说明、长文找信息），需要评审。

三种打分方式

方式怎么做适合哪类题
规则自动判有确定答案的直接比对，如 549、JSON 字段计算、抽取、格式
评审模型盲评第三个模型看两个回答，不知道哪个是官方；A/B 位置换过来再评一次，两次结论一致才算胜负写作、代码、摘要
人工盲评工作人员看两个回答（来源隐藏），选更好的抽查评审模型是否靠谱

怎么操作

  1. 先在“评测 Key”存好官方 Key。
  2. 选供应商型号、对照的官方型号、评审模型、思考模式，可展开“看题目”。
  3. 点开始，跑完后看每题的规则结果和评审结论；有空时做几题人工盲评。

Agent 对比

同一个 Agent 做同一组任务，走我们和走官方，最后交付一样好吗？

  • 测试 Key 以 sf_eval_ 开头，由工作人员持有，不扣员工额度，保存完整对话，对比结束即作废。

压测

这个模型在我们的线路上能扛多少并发？

三种负载画像

画像输入输出看什么
短问答一句话约 60 字首字延迟、排队
常规对话约 2 千字约 300 字接近员工日常
长上下文约 2 万字约 100 字长输入下的排队（费用最高）

怎么操作

  1. 选型号、画像，勾选要跑的并发档（1、2、4、8、12、16、24、32）。
  2. 页面会按最长回答估算最高花费，超过预算（最多 ¥20）的不允许启动。第一次先用“短问答 + 1、2、4”试一次，费用不到 1 毛。
  3. 点 开始压测；随时可以点 停止压测。

“稳定并发”怎么算

  • 从第一档开始，连续满足两条的最高并发：
  • ① 成功率 ≥ 98%；
  • ② 首字延迟 P95 不超过“最轻那一档的 3 倍”和“最轻那一档 + 2 秒”中较大的那个。
  • 安全阀：最多 32 并发、240 次请求；某档失败率超过 20% 立即停止；单个请求 120 秒超时。

运行观测与 Key 巡检

现在线上有没有异常？

巡检会告诉你什么

情况系统怎么做你要做什么
上游新增了我们已定价的型号自动上线，发信息邮件不用
上游新增了未定价的型号发警告邮件在型号与费率里定价，再上线
上游下架了在售型号，或 Key 不响应发严重告警邮件联系供应商；必要时暂停模型
两把 Key 其实是同一把发警告新建一把真正的备用 Key
某个型号不守 max_tokens自动启用输出保护不用；上游修好后自动解除

输出保护是什么

有的上游会忽略“最多输出 N 个 Token”的要求（实测 GLM-5.3-FlashX 要 16 个给了 200～1500 个）。网关对这类型号改为流式读取，数到上限就关掉上游连接，返回 finish_reason=length，行为和官方一致。被截断的那次没有可信的用量数字，计费以供应商日志为准。

事件会一直保持“打开”，直到某次巡检不再看到它。页面上方的数字是近 7 天内部测试的汇总：成功率、可核对响应、费用待核、P95 耗时。

路由与熔断

出问题时，能不能马上止损？

  • 表格显示每个模型走哪条上游、状态、30 天调用、失败数、P95 延迟。
  • 暂停后员工调用该模型会马上失败并看到提示，用于上游出严重问题（被换模型、大面积报错）时止损。
  • 自动切换要有真正不同的备用 Key 才有意义。

结论意思
计量及规则复算一致Token 一致，按规则算出的钱和上游实扣一致

词意思
Token模型计费和计数的单位。中文大约 1 个字 ≈ 1 个 Token，英文 1 个词 ≈ 1～1.3 个 Token
输入 / 输出 / 缓存 Token发给模型的、模型写出来的、命中缓存的（更便宜）
分词器把文字切成 Token 的规则。每个模型家族各不相同，所以能当“指纹”
首字延迟（TTFT）从发出请求到收到第一个字的时间
P9595% 的请求都不超过这个值
finish_reason回答结束的原因：stop 正常结束；length 到了输出上限被截断；tool_calls 要调用工具
流式（stream）边生成边返回，像打字一样一个字一个字出来
量化把模型的数字精度降低，换来更便宜、更快，但能力会下降
参照端点官方 API 的测试入口，只用于对比，不参与路由
盲评换位评审时隐藏来源，A/B 对调再评一次，两次一致才算数
输出保护上游不守 max_tokens 时，网关代为计数并截断
