# 中美区域与合规设计

本章把可核实的规则转成产品和系统边界。它不是对尚未确定的经营主体、合同、客户数据和资金流的全面法律结论。每个地区上线前应由相应法律、税务和支付专业人员确认实际适用事项。

## 区域比较

| 项目 | 中国区设计 | 美国区设计 |
| --- | --- | --- |
| 客户体验 | 中文优先，人民币，国内可用登录与支付方式 | 英文优先，美元，相应登录与支付方式 |
| 主体与交易 | 经确认的签约主体、收款商户与开票主体 | 经确认的签约主体、商户、税务及退款责任 |
| 供应服务 | 已核实授权、备案/登记关系和数据路径的通道 | 已核实交易主体、出口限制和数据路径的通道 |
| 数据 | 区内身份、数据库、凭据、日志、队列和备份 | 区内身份、数据库、凭据、日志、队列和备份 |
| 票据 | 交易凭证、消费账单、适用税务发票 | invoice、receipt、credit note 及适用税项 |
| 跨区行为 | 不默认迁移余额、提示词或后台数据 | 不默认使用中国端点或中国运维访问 |
| 模型可售性 | 按具体商品与通道审批 | 同一家族重新按美国供应路径审批 |

以上区域隔离是降低复杂度的架构建议，不代表所有数据法律上一律必须留在本地，也不表示系统部署完毕就获得合规许可。

## 中国区需要落实的事项

互联网信息服务的备案和经营许可、在线数据处理与交易处理的业务分类应按实际服务确定，不能把 ICP 备案、ICP 许可和 EDI 当成同一手续。是否需要具体许可，取决于合同、服务与交易结构，不能凭“自营网站”或“收费 API”四个字下结论。[S01](11-sources.md#s01)[S24](11-sources.md#s24)

《生成式人工智能服务管理暂行办法》涉及向境内公众提供生成内容的服务，定义包含 API 方式。2026 年 9 月的网信办公告说明，直接调用已备案模型能力的应用或功能由地方网信办开展登记。平台需要识别自身适用的程序和信息展示要求，不能把上游备案当作自己的全部手续。[S02](11-sources.md#s02)[S03](11-sources.md#s03)

内容治理、投诉处理与生成合成内容标识进入发布验收。Playground 明示 AI 生成；API、文件及流式输出按其适用标准设计标识传递和元数据，避免无条件删除上游标识，也不采用破坏协议的统一硬编码前缀。[S04](11-sources.md#s04)

数据出境规则按数据类别、数量、主体及具体情形规定不同机制和豁免。设计默认中国区内处理，但仍建立提示词、身份、日志、客服和分析 SDK 的数据流清单，逐项识别实际出境及接收方。[S05](11-sources.md#s05)

人民币收款使用银行或持牌机构的适当商户产品。首期限制平台额度用途，不自建资金转移、提现和商家托管；具体预付服务、消费者退款及未来多方清分安排仍须确认。[S25](11-sources.md#s25)

推荐、代理、分销制度须审查计酬基础和组织结构。“真实销售”并不保证任意多层佣金合法。首期只开放直接归因、真实消费的单层推荐，多层结算以单独法律和合同判断为前提。[S06](11-sources.md#s06)

## 美国区需要落实的事项

美国隐私义务按州、业务角色和适用条件确定。CCPA 涉及适用门槛，同时对服务提供者和承包方有相关要求；企业联系人和员工也可能是受保护的自然人。账户资料与代客户处理的提示词应分别定义目的、角色、DPA、子处理者及权利响应机制。[S14](11-sources.md#s14)

DOJ Data Security Program 对特定美国政府相关数据、达到门槛的敏感个人数据及相关交易施加禁止或限制，并不等于禁止所有普通 API 调用。风险判断要包括模型供应商、远程员工、日志、备份和支持访问。美国服务器加中国上游不能自动宣称全程美国处理；加密或客户同意也不能自动排除规则适用。[S12](11-sources.md#s12)

BIS 当前 Entity List 包含北京智谱华章，别名 Zhipu AI。它涉及受 EAR 管辖物项的有关出口、再出口和转移要求，不能直接等同 OFAC 全面制裁或“所有 GLM 使用都非法”。美国区要对合同法人、技术流向、供应链及具体交易核查，未完成前不批准相应销售商品。[S15](11-sources.md#s15)

支付机构按商户所在地区和实际业务批准服务；语言切换不改变商户资格。收款主体、网站合同、票据、账单描述和退款责任需要一致。销售税的 nexus、产品税性、登记与申报按适用州处理，启用税务软件不等于已经完成登记。[S08](11-sources.md#s08)[S13](11-sources.md#s13)

## 将合规判断做成可执行策略

每个 SupplierModelOffer 至少关联：供应商法人、销售地区、实际推理地点、日志与备份地点、训练用途、授权期限、允许客户类型、分销权限、审批状态和证据引用。

审批状态为 draft、review_required、approved、suspended、expired。只有 approved 且未过期的通道可进入生产候选集。不能用一个 us_compliant 布尔值表达所有法律与数据条件。

每笔请求保存采用的数据路径策略版本。每次变更供应商、数据留存、处理地区或交易主体，都触发对应商品的重新评估。中央经营看板只接收经过审查的必要汇总；不能把原始提示词、实名资料和完整支付资料默认汇集到全球后台。

## 发布前的具体证据

发布记录应关联经营主体与许可判断、供应商授权、生成式 AI 相关备案/登记或适用意见、内容与标识方案、数据流与跨境判断、支付商户批准、退款及税务方案、渠道协议、软件许可证和安全验收。

医疗、政府、未成年人等具有特殊要求的客户或用途，单独定义是否接受及所需合同条件。首期不在未审核时宣传支持所有行业或处理所有敏感数据。
