# 账户注册与登录方案（2026-11-18）

## 当前事实

现有 customerAuth 使用 Better Auth，支持邮箱密码注册、邮箱验证、邮件重置密码；当前密码长度为 12–128，重置密码会撤销其他会话。个人、企业成员共享客户身份；内部员工另有身份体系。微信支付、支付宝支付不等于扫码登录授权，不能复用支付二维码作为登录凭据。

## 建议交互

- 同一个登录入口，提供「手机验证码」「账号密码」「扫码登录」。账号密码接受已验证手机号或邮箱。桌面扫码区切换微信/支付宝；手机浏览器按平台支持跳授权页，不能跳时显示其他登录方式。
- 注册：手机号 + 验证码，或邮箱 + 验证邮件；用户明确同意服务条款和隐私政策后创建账户。未注册号码登录时先提示将创建账户，禁止静默注册。
- 扫码后已有绑定直接登录；首次使用先验证手机或邮箱，明确选择绑定已有账号或新建账号。不得凭昵称、头像、未验证邮箱合并账户。
- 密码规则按用户要求：8–128 个字符，必须包含 ASCII 大写、小写及标点符号；数字允许但不强制。空格不算符号。页面显示逐项要求和显示密码按钮，允许密码管理器及粘贴。注册、设置密码、修改、重置共享服务端校验，旧密码可继续登录，下一次修改时执行新规则。
- 忘记密码：选择已绑定手机号或邮箱；手机验证码验证后设置新密码，邮箱使用一次性限时重置链接。对外统一返回提示，不暴露账户是否存在。重置后撤销旧会话并发送安全通知。
- 设置中心：手机号、邮箱、微信、支付宝绑定状态，修改/解绑需近期重新验证，不能解绑最后一种可恢复的登录方式。账户合并必须验证两边身份，余额和企业权限不能直接迁移。

## 数据与服务

保持唯一 user_id，余额、订单、API Key、企业成员关系仍归属原 user_id。新增已验证号码和外部身份映射（provider、app_id、subject 唯一约束；微信 UnionID 仅在可用且来源可信时辅助关联）。不得伪造邮箱满足现有邮箱必填字段；先验证 Better Auth 当前版本的 phoneNumber/自定义 OAuth 能力及现有表兼容性，再选择插件或显式适配层。

提供服务端能力配置，只显示已经配置且验收通过的登录方式。OAuth 使用随机一次性 state、浏览器会话绑定、短时有效的扫码会话；服务端兑换授权码并核验应用身份，禁止客户端传用户 ID 直接登录。二维码状态仅由受信服务端授权结果推进，扫码确认与网页会话须绑定，轮询过期后停止。回跳地址采用站内允许列表。

验证码使用安全随机数，哈希存储、一次性消费、用途隔离、5 分钟有效；初始规则建议发送间隔 60 秒，单次最多 5 次尝试，并限制号码/IP/设备的每小时和每天发送量。登录、注册、找回密码、绑定不得互用验证码；验证与消费必须原子执行。供应商超时不宣称发送成功。日志不记录验证码、密码、授权码或 token。

## 平台接入条件

| 方式 | 需要落实 | 验收条件 |
| --- | --- | --- |
| 邮箱 | 继续使用现有邮件队列与发信配置 | 注册验证、重置链接、过期/重放、投递失败可恢复 |
| 手机 | 选择短信供应商，完成资质、签名、验证码模板和适用报备；或评估托管验证码认证服务 | 真机接收、频控、错误次数、过期、并发一次性消费 |
| 微信 | 核对开放平台网站应用能力、主体认证、应用审核及授权回调域名；公众号支付配置不能视为已满足 | 桌面扫码、取消、过期、回调重放、微信内移动端路径 |
| 支付宝 | 核对当前开放平台应用是否获准面向该网站的用户授权能力、回调域名与签名配置 | 官方授权结果绑定浏览器登录会话、取消、过期、验签与重放 |

## 实施次序与验收

1. 先稳定全站框架和加载；身份功能本轮只提交方案，不变更生产密码规则。
2. 做统一身份模型、密码规则、邮箱恢复及绑定设置，回归现有用户登录与余额归属。
3. 接入手机验证码并通过真机验收，再开放注册与手机恢复。
4. 微信、支付宝分别以能力开关上线；有一项未审核通过不影响其他方式。上线前完成串号、扫码劫持、回调重放、验证码刷取和账户枚举测试。

外部待办：确认申请主体、最终登录域名、短信方案，以及微信/支付宝应用授权能力。不要在聊天或文档中提交密钥；沿用服务器密钥管理流程。工期需在平台权限、审核与短信配置明确后估算，不把外部审核时间承诺为开发工期。
