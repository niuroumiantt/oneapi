# 网关设置与要求登记表

> 这份表登记 semifly.ai 网关（员工调用 `/v1/chat/completions` 走的那一层）**现在每一条设置是多少、写在哪里、是谁定的、对员工有什么影响**。
> 目的是让公司对网关的每一条要求都有明确决定。凡是标 **⚠ 待确认** 的，都是开发时定的默认值，**没有经过负责人确认**；标 **❗ 有问题** 的，是已经发现现行设置有缺陷。
> 核对日期：2026-11-12。代码版本 `6e003b0`，生产镜像 `a00859e`。现行值一栏同时核对了生产数据库和服务器 Caddy 配置。

**来源一栏的含义**

| 标记 | 含义 |
|---|---|
| ✅ 已定 | 有明确依据：负责人提过的要求、官方规则，或实测结论 |
| ⚠ 待确认 | 开发时定的默认值，没有记录理由，没有经过负责人确认 |
| ❗ 有问题 | 现行设置有已知缺陷，需要决定怎么改 |

---

## 0. 请求走的路

```
员工的工具 → Caddy（服务器入口）→ semifly 网关（Node 服务）→ KerAPI → 模型
```

每一层都有自己的限制。一条请求必须同时满足所有层的限制。

## D. 超时与断开

| 编号 | 设置 | 现行值 | 来源 | 对员工的影响 |
|---|---|---|---|---|
| D1 | 网关等上游的总时长 | 300 秒，从发出请求算起，**包含流式输出的全过程** | ⚠ 待确认 | 一次请求最长 5 分钟，到时网关主动断开上游 |
| D2 | Caddy 等网关的时长 | `/v1` 是 310 秒（等到响应头为止） | ⚠ 待确认（比 D1 多 10 秒，让网关先给出可读的错误） | — |
| D3 | 首字超时、空闲超时 | **没有** | ⚠ 待确认 | 上游卡住不出字时，要等满 300 秒才报错 |
| D4 | 员工的工具先断开时 | 网关立即关闭上游请求，这次调用记为失败，不扣员工额度 | ❗ 有问题 | 见下方「D1 与 D4 的问题」 |
| D5 | 非员工接口（`/api/*`）| 请求体 16 KB，等待 60 秒 | ✅ 已定 | 只影响网页后台 |

**D1 的来历**：300 秒是 2026-11-10 第一版员工额度功能里写进去的，之后没有改过，代码和文档里都没有记录理由。它不是任何人提出的要求。到核对时为止，生产上还没有一次请求真正触发过这个 300 秒超时。本地实测确认过：超时到点时，正在进行的流式输出会被直接切断。

**D1 与 D4 的问题**

1. **300 秒和 32K 输出上限互相矛盾。** GLM-5.3 实测约 50 Token/秒，写满 32768 个 Token 要约 650 秒；DeepSeek Flash 约 100 Token/秒，要约 330 秒。所以长回答写不完就会被 300 秒切断：GLM-5.3 实际最多约 1.5 万 Token。流式请求被切断时，员工只看到输出突然停止，没有截断标记，也没有报错。
2. **断开被记成“上游失败”。** 员工的工具自己超时断开，库里记的是 `UPSTREAM_FAILED`。截至核对时共有 114 次这样的记录，其中 110 次集中在 59–61 秒，是调用方脚本自己的 60 秒超时，不是 KerAPI 的问题。
3. **断开后谁付钱没有规则。** 上游在被关闭前已经生成的内容，KerAPI 可能照常向我们收费；而我们对员工记的是“失败，不扣额度”。这部分成本目前由公司承担，也没有单独统计。

## J. 返回给员工的错误

| 状态码 | 什么时候 | 来源 |
|---|---|---|
| 400 | 请求格式不对（见 B2、B3、B4） | ✅ 已定 |
| 401 | Key 无效或已停用 | ✅ 已定 |
| 402 | 余额不够预留，或 Key 到了消费上限 | ✅ 已定 |
| 403 | 模型未开放，或这把 Key 不允许调这个模型 | ✅ 已定 |
| 413 | 请求超过 8 MB | ✅ 已定 |
| 429 | 超过每分钟次数或并发（**这是我们网关自己的限制，不是 KerAPI 的**） | ✅ 已定 |
| 502 | 上游失败、超时，或上游返回 5xx | ✅ 已定 |
| 503 | 模型暂停或没有线路 | ✅ 已定 |
| 上游的 4xx | 原样透传状态码和上游的错误信息 | ⚠ 待确认 |

每个错误都带错误码、请求编号和文档链接；响应头有 `X-Semifly-Request-Id`，成功的调用还有 `X-Semifly-Call-Id`。

## 这份表怎么维护

- 改任何一条网关设置时，同一个提交里更新这份表。
- 每条设置在代码里的位置：
  - 请求限制、频率、并发、超时、计费：`server/src/employee-credit.mjs` 开头的常量和 `/v1/chat/completions` 处理函数。
  - 模型目录、价格、高峰规则：`server/src/official-models.mjs`。
  - 输出保护：`server/src/output-guard.mjs`。
  - 服务器入口：infra 仓库里的 Caddy 配置，`oneapi.glocalstorage.cn` 一段。
  - 按 Key 调高的并发和频率：数据库 `employee_api_keys.max_concurrent`、`per_minute`。
- 员工看到的说明在 `web/docs.js`（`#docs` 页的“限制”和“错误码”），改设置时要一起改。
