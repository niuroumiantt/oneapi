# 产品模块与职责

建议划分为 18 个业务模块。模块首先表示代码和业务职责，不等于 18 个独立微服务。首期可以由同一个业务服务和数据库承载，逐步按压力拆分。

阶段说明：P0 为设计与接入验证；P1 为中国区受控上线；P2 为企业与渠道增强；P3 为完成独立准入后的美国区及规模化能力。任何地区的实际商用都以前置授权与合规条件满足为前提。

## 模块之间如何协作

供应商模块记录“向谁采购”；目录模块记录“对外卖什么”；定价模块记录“按什么规则卖”；网关模块决定“这次请求可以交给谁”；计费模块将真实用量转换成费用；账本模块记录经济效果。

渠道模块记录客户与合作方的商业关系。推荐模块只负责活动与归因。佣金模块根据已生效的规则和合格消费计算应付。渠道人员不能直接修改客户余额，也不能通过换一个推荐码重写历史佣金。

客户控制台和员工后台都是业务模块的界面。后台页面点击“退款”必须调用退款业务流程，不能直接更新数据库金额。财务人员在控制台看到的数字应能追溯到同一批账本分录和消费记录。

## 模块完成标准

每个模块必须有一句职责说明、主要数据对象、输入输出、权限要求、异常状态和验收场景。只创建文件夹、接口占位或空页面，不视为功能完成。

## 首版用户路径

个人路径：选择区域 → 注册并完成适用验证 → 查看模型与价格 → 支付取得消费额度 → 创建项目和 Key → 完成首个 API 请求 → 查看用量和余额 → 下载账单或提交开票申请。

企业路径：建立企业组织 → 邀请采购、财务和开发成员 → 核实主体和采购要求 → 接受报价/合同 → 提交 PO 或预付 → 审批预算或授信 → 按项目使用 → 按期对账、开票、付款和核销。

渠道路径：申请合作 → 完成审核并签协议 → 开通明确的角色权限 → 报备客户或取得批发服务 → 根据真实交易获得佣金或销售差价 → 处理结算及售后。

供应商路径：提交主体、授权及端点资料 → 合同和数据路径审核 → 协议与质量测试 → 小流量观察 → 允许上架 → 持续监控、调价和对账 → 到期复核或停用。
