分支 `codex/model-pack-ledger-20261127`，基线 `2b40b92`。在独立工作树完成，使用本地 PostgreSQL、模拟支付渠道和测试用量。此次范围为本地验收。

## 账本规则

- 新模型促销码绑定唯一正式网关模型 ID 与折扣。开启 `CW_MODEL_PACKS_ENABLED=true` 后，新 VIP 码必须选模型。历史通用码、本人付款码、通用额度和企业账户沿用现有逻辑。
- 模型必须在 `CUSTOMER_PAID_MODELS` 且有启用的 `model_pack_offers` 报价。迁移 092 不预置业务价格。按模型配置最低客户实付比例与 VIP 结算比例（万分位）；调整时在同一事务停用旧版、插入新版。下单重新核对报价，已下单的支付、消费和退款以订单快照为准。
- 网关以规范模型 ID 检查额度，先用该模型的批次、按入账时间先后使用，再用通用余额。进行中的同模型调用及其他模型需要的通用额度都保留。实付和赠送按购买比例累计扣减，兼容分以下的用量，现金按分入账。赠送按原有效期，未消费实付依原单退款资格处理。
- VIP 提成按实际消费的累计报价差额计提，向下取整到分且不超过已确认的消费实付。以累计差额取整，可避免跨月时两个独立取整结果造成已计提金额倒退。付款本身没有已记提成；成功退款退剩余合资格实付、取消剩余赠送、保留已消耗提成。渠道失败恢复原冻结。提现仍使用现有月结和财务确认。
- 正式月结沿用现有脱敏 PDF 流程。模型包记录附模型名和消费额度，VIP 本人用量与推广数据分开。旧批次未改用比例扣减，迁移可重复执行。
