# VIP 销售跟进与付款码交接（2026-11-25，m5）

## 入口与权限

- 商务后台的「客户」下进入「VIP 客户跟进」，老板驾驶舱显示待面试和待特批数量。管理员查看全部范围，负责销售查看自己名下的客户和发出的邀请码。归属以邀请码创建人初始化，管理员可以改派，跟进记录随客户保留。
- 历史申请通过 `cw.applied` 审计中的邀请码回填来源。没有匹配记录的申请由管理员分配。联系方式在站内需要记录查阅原因。新申请的管理员通知含联系方式、客户资料、来源和北京时间，负责销售收到简要通知。通知直达档案，员工登录后返回目标档案。
- 面试通过后，负责销售与管理员都可生成默认 5 折付款码。其他折扣须填写理由并由管理员审批。通过时换发专属付款码，旧码停止用于新充值。退回保留原码。申请人看到当前可用码，可点击链接预填个人充值页。
- 充值后仍由销售确认开通。待面试、待充值和正式会员界面按申请状态显示。

## 验证与发布

用临时 PostgreSQL 验证归属回填、跨销售访问隔离、通知回执、并发生成、退回和审批、代码仅限本人以及现金报价。用本地 Chrome 模拟销售、管理员和申请人在手机端查码、提交特批和完成金额核对。测试未操作线上申请、发信或付款。上线需同时部署 `083_vip_sales_followup.sql`、`084_vip_payment_discount_approvals.sql` 和对应前端。
