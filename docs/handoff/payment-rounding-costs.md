# 金额取整、支付渠道成本与特批退款

2026-11-14，m5。用户授权完成测试后发布，复用已有页面。

- 面板余额四舍五入至分，精确账本保留；小于一分的累计已用显示“不足 ¥0.01”。退款按剩余实付比例扣服务费后，最终四舍五入到分。
- 原收款退款页增加全部已付款渠道及客户汇总，交易订单继续逐笔展示。渠道费按真实商户账单登记，支持零费用和带版本检查的更正；权限为财务，审计保存更正前后金额与凭据说明。不从客户账户扣除，不猜费率；未核对明确计数。
- 经营损益分列渠道成本与扣渠道费后的经营收益，现金流扣除渠道成本。成本归原付款月份，目前手工核对实际商户账单，未实现自动下载账单。
- 平台管理员可在原退款弹窗特批服务费 0–14%，原因必填；保存标准退款额、比例、审批人和时间。财务只能按标准费率退款。幂等键不允许改动审批条件。
- 数据库迁移 062 只加字段，历史已执行退款不会重算。已有的支付开关、商户配置和模型开放范围不变。
- 验证：独立 PostgreSQL 16 测试库，89 项测试全通过；Chrome 本地虚构数据检查汇总、退款弹窗和减免预览，无运行时异常。截图和日志在本机临时目录，不包含真实支付凭证。
- 发布后应确认 API / 静态版本一致、迁移字段存在、已有余额与退款金额未改变。真实渠道费用仍需按商户账单核对登记。
