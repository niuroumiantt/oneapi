# 员工邀请、移除与公司额度池

## 范围与入口

老板已通过公司 SSO 登录。新增 `/#staff-team`（员工与邀请）和 `/#staff-team/usage`（公司 API 用量），从 `/#staff-account` 的“公司员工与额度”进入。复用 `identity.js` 的企业成员、邀请、审批、额度和用量组件，不新增员工 API 模板。

`/api/staff/company/*` 要求有效 platform_admin 会话，并绑定到配置公司中唯一、已验证、未禁用的 owner 用户。普通员工及跨公司请求被后端拒绝。个人登录不能代替公司 SSO 的老板权限。

## 已实现

- 邀请链接、申请、老板审批继续使用现有企业流程；已移除或拒绝的人可重新提交，旧审批结果写入审计。
- 配置公司的新员工获批时创建零额度账户，由老板从公司池分配。审批只赋予已在身份中心认证的匹配账号 operations；不授予 platform_admin。尚未登录过的员工在通过身份中心原有准入策略后，回调核对已批准的申请，再启用普通岗位。
- 移除会永久撤销旧员工 API Key，暂停匹配的普通员工运营身份、删除会话，保留个人账号及历史调用。再次邀请、审批后仍须使用新 Key。
- 未使用额度回到 `company_credit_pools`，账本 `company_credit_ledger` 记录每次增减。已消费不退；pending/awaiting_bill 预留先保留，结算 worker 稍后释放余额。重复回收不会重复入池。
- 移除、额度调整按 organization → account 顺序加锁；API 预留和创建 Key 在 account 锁内再次确认成员关系。重新加入但旧调用未结算时禁止再次分配，避免收回新额度。
- 公司预算由老板显式增加，追加/调整额度扣公司池；减少额度回池。池初始为零，不改变现有已分配额度。它是内部 API 使用预算，不是客户现金、充值或退款。
