# 官价额度包计费（2026-11-13 负责人定稿）

> 取代「调用时再打折」的思路。计量永远按官网价；折扣只发生在**购买额度包付款时**。

## 模型

1. **计量货币**：Token × 官网价（与官方 API、员工额度同一套）。系统 IT / 缓存命中 / 吞吐 / 上游对账都只认这一套。
2. **售卖物**：官价额度包。面额 F = 按官网价可消费的金额（元）。
3. **折扣**：付款前用合同价或促销码；**只取最优一条，不叠加**。算出实付 C。付款后订单锁定，不可改。
4. **入账**：现金侧记实付 C（营收、发票、退款基数）；额度侧记面额 F（客户面板与调用扣费）。
5. **调用**：一律按官网价扣官价额度 F，不按客户折扣率改单价。

例：面额 ¥100 的包。客户 A 实付 ¥30，客户 B 实付 ¥40。两人面板都看到约 ¥100 官价额度；财务分别看到实收 30 / 40。

## 客户面板

- **默认只展示官价额度**（还可按官网价使用多少）。
- **实付、可开票、可退说明**只在账单 / 发票页。

## 财务与发票

- 营收、可开票额度按**实付**累计（充值入账 − 退款 − 已申请/已开具发票）。
- 不按面板官价额度开票。

## 退款（2026-11-13）

对某一笔入账（面额 F、实付 C、剩余官价额度 R）：

1. **已开具且未作废/未红冲的销项发票**（该客户名下）→ **整笔不可退**（「已开发票的不退款」）。
2. 否则应退现金（分）为：

   `floor( (R / F) * C * (1 - 0.15) )`

   即：按**未使用官价额度占比**乘以**该笔实付**，再扣 **15% 手续费**。
3. 退款说明文案须写明上述规则。
4. 退款成功后：扣减剩余官价额度 R，现金侧记退款流水。

在线支付原路退、对公退款都遵守同一公式（对公可能走线下打款 + 账本冲减，渠道不同、公式相同）。

## 对公转账

「财务登记 + 第二人复核后入账」（2026-11-13）：

- 登记：客户、**实付金额**、**官价额度面额**（无折扣时默认面额=实付）、到账日、回单号/备注。状态 `pending`，不改余额。
- 复核：另一人（不可为登记人）对照银行流水通过 → 入账实付流水 + 增加官价额度；驳回则不变。

金额计算只在最后取整：`floor(R * C * 85 / (F * 100))`，不要先把 `R*C/F` 截成整数分再乘 85%。账户现金按累计消耗取整，退款结清时不足一分的比例尾差归入手续费，以保持整个批次现金守恒。
