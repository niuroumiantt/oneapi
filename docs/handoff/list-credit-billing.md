# 官价额度包计费（2026-11-13 负责人定稿）

> 取代「调用时再打折」的思路。计量永远按官网价；折扣只发生在**购买额度包付款时**。

## 模型

1. **计量货币**：Token × 官网价（与官方 API、员工额度同一套）。系统 IT / 缓存命中 / 吞吐 / 上游对账都只认这一套。
2. **售卖物**：官价额度包。面额 F = 按官网价可消费的金额（元）。
3. **折扣**：付款前用合同价或促销码；**只取最优一条，不叠加**。算出实付 C。付款后订单锁定，不可改。
4. **入账**：现金侧记实付 C（营收、发票、退款基数）；额度侧记面额 F（客户面板与调用扣费）。
5. **调用**：一律按官网价扣官价额度 F，不按客户折扣率改单价。

例：面额 ¥100 的包。客户 A 实付 ¥30，客户 B 实付 ¥40。两人面板都看到约 ¥100 官价额度；财务分别看到实收 30 / 40。

## 客户面板

- **默认只展示官价额度**（还可按官网价使用多少）。
- **实付、可开票、可退说明**只在账单 / 发票页。

## 财务与发票（2026-11-21 负责人定稿：退款与发票统一政策）

开票和退款是**同一笔实付 C 的两端，互斥不重叠**，这是整套政策的地基：

- 发票按**客户实际付款金额**开具，与折扣率、官价面额 F 无关；不按面板官价额度开票。
- 可开票金额 = 累计实付 − 已退款 − 已申请/已开具发票（红冲/作废后额度恢复）。
- **充值即可开票**（不必等使用）；**付款后 30 天内均可申请开票**。
- **开票后不可退款**：只要账户下有已申请(requested)或已开具(issued)的销项发票，就锁定该账户的自助退款，需先作废或红冲发票。反之，客户先退款后，那部分实付不再有开票额度。
- 客户选择退款时，只退红条实付剩余 R = C − U；已消耗实付 U 因未退款，仍留在可开票额度里（"实付的实用的，依然可以开票"）。

三条客户规则（原话口径）：

1. 充值就可以开发票，发票是实付价格；开票不可以退款。
2. 未开票的情况下可退款，在红条实付可退范围内退；已消耗的那部分实付依然可以开票。
3. 没有退款、即使用完，付款后 30 天内都可以开票。

## 退款（2026-11-21 负责人改为红绿模型，取代原 15% 手续费规则）

进度条按官价面额 F 铺满：左段绿色 = 赠送（F − C），右段红色 = 实付 C。调用按官价扣减，**先扣红再扣绿**，`consumed_cash_fen = min(C, floor(累计官价消耗))`。对某一笔入账（面额 F、实付 C、剩余官价 R、已核销实付 U）：

1. **红剩余** `R_red = C − U`：这是客户自己花的钱，**可退，且不收手续费**。
2. **绿剩余** `R_green = R − R_red`：这是因付款而赠，退款时**整条收回**，不是退款基数。
3. 该账户已申请(requested)或已开具(issued)销项发票 → 开票后不可退款，需先作废或红冲；在途调用 → 先结算；红剩余为 0 → 无可退金额。对公转账 → 财务人工处理。
4. 退款执行：冻结该包（剩余额度归零）、原路退 `R_red`、关闭额度包（绿永久回收）；渠道明确拒绝则恢复冻结前的 R 与 U。

例：3 折买 ¥100（实付 ¥30，绿 ¥70）。用掉 ¥10 官价后红剩 ¥20、绿 ¥70。客户退款 → 退 ¥20，¥70 赠送整条收回，包关闭。若已用满 ¥30 实付（红=0），则无可退金额，剩余绿继续可用。

在线支付由客户在账单页自助原路退；对公由财务在工作台人工处理。两者都遵守同一红绿口径。

## 对公转账

「财务登记 + 第二人复核后入账」（2026-11-13）：

- 登记：客户、**实付金额**、**官价额度面额**（无折扣时默认面额=实付）、到账日、回单号/备注。状态 `pending`，不改余额。
- 复核：另一人（不可为登记人）对照银行流水通过 → 入账实付流水 + 增加官价额度；驳回则不变。

- 客户购包按面额完整到账；支付渠道手续费不抵扣客户额度。面板余额四舍五入显示两位小数，精确账本不变；不足一分的已用显示“不足 ¥0.01”。

- 已下线服务费比例与特批减免：退款一律无手续费，财务弹窗不再提供费率调整。
- 收款退款页按渠道和付款客户统计成功交易次数、金额，逐笔保留支付/退款记录。渠道费用按商户真实账单由财务核对登记（支持明确为零），更正保存审计；未核对显示待核对，不能当作零成本。成本归属原付款月份；目前按账单手工核对，尚未自动下载支付宝账单。
