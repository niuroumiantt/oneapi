# 员工工作台本地评审（2026-11-26，m5）

## 用户确认的范围（本轮纠正优先）
- 企业员工负责招揽顾客、招揽 VIP、管理自己负责的客户、客户服务与流程跟进。
- 经营损益、供应商、公司资金、审批和权限管理属于独立的老板身份。不能通过普通员工的历史财务/技术开关扩大权限。
- 用户只授权本地运行，不推送、不部署公网；保留个人界面的视觉体系。

## 本轮实现
- 员工导航按用户后续要求拆分：今日工作；客户推广（客户概览、客户推广码、我的申请）；VIP推广（VIP概览、VIP推广码、我的申请）；客户服务（我的客户、客户服务）。
- 老板工作台单独使用 `#console/owner/overview`，服务端按有效 `platform_admin` 身份验证；员工页面不展示公司经营/供应菜单。
- `staff-policy.mjs` 对真实员工认证后的接口实行白名单；未列出的接口默认拒绝。历史 finance_access / technical_access 不再扩大普通员工权限。老板的全公司访问权保留。
- 客户列表、详情、标签统计和工单读写按 `customers.owner_subject` 限制。未分配客户不对员工公开；员工可写跟进记录、保存客户阶段、回复和分流自己客户的工单，不能转移客户、改优惠分群或审批资金。
- 客户资料/跟进写入在事务内锁定归属。工单按当前个人客户归属过滤；持有企业客户不自动获得其成员的个人工单。
- 获客/VIP 沿用既有按发码人或负责人范围查询的流程。客户码和 VIP 归属不自动迁移为 CRM 客户归属，老板需要分配 CRM 客户。

## 本地评审入口
- 员工：http://127.0.0.1:3326/?identity=employee#console/business/home
- 老板：http://127.0.0.1:3326/?identity=owner#console/owner/overview
- 启动：`node scripts/dev/staff-preview.mjs`，仅监听 127.0.0.1；可用 STAFF_PREVIEW_PORT 更换端口。
- 默认进入员工身份（包括旧的 role 参数链接）。顶部可切换两个示例身份；它只是本地评审器，不是真实登录。
- 仅使用内存示例数据，不读生产配置或凭据，不代理公网。示例客户跟进、阶段保存、工单回复/分流可操作，重启清空；其他写入明确提示未接入。
- VIP 独立页面仍是说明入口，完整 VIP 本地交互尚未接入。没有测试真实 OIDC、付款、退款或生产运行。
