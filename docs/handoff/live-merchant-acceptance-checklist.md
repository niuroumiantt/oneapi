# 真实商户小额闭环验收清单

> 2026-11-24。用途：在打开 `CUSTOMER_PAID_ENABLED` 和客户可见支付入口前，逐项确认代码、配置、资金与业务证据。任何一项未通过，不把付费调用视为可发布。本文是发布门槛清单，不记录真实客户资料或密钥。

## 0. 前置门禁（未完成则不进入真实验收）

- [ ] 首个可售模型的商业授权、转售范围、数据路径和人民币客户价已由负责人批准。
- [ ] 支付商户已开通，且商户主体、域名、回调地址与 README / 部署文档一致。
- [ ] 数据库备份完成，迁移 `001`–`069` 在候选环境全部应用；测试只用独立空库，不碰生产。
- [ ] 当前代码、静态包与 API 镜像版本一致，`/api/status` 与 `/release.json` 的 SHA 已记录。
- [ ] `CUSTOMER_PAID_ENABLED=false`、`CUSTOMER_PAID_MODELS` 未配置或仅含已验收模型；验收期间按白名单和 `ALIPAY_ALLOWED_EMAILS` 之类限制放量。
- [ ] 回滚镜像、配置备份、数据库备份路径已确认，且验证过回滚步骤。

## 1. 购包报价与订单

- [ ] 用白名单账号在账单页选面额 F，报价返回最优单条优惠，不叠加；促销码无效时明确拒绝。
- [ ] 订单快照锁定 `face_fen`、`amount_fen`、`discount_snapshot`；重复提交同一幂等键返回同一订单。
- [ ] 折扣预算上限包含 pending 订单，过期 pending 不自动释放（防迟到通知突破预算）。
- [ ] 客户面板显示官价面额 F 与红绿拆分；实付、可开票和可退说明只在账单/发票页出现。
- [ ] 报价不是收款凭证：未支付不产生额度包、不产生 Key 权限。

## 2. 支付确认与入账

- [ ] 支付宝电脑网站支付或微信 Native 的小额真实付款（建议 ¥5）成功跳转/出码。
- [ ] 异步通知验签、商户号、订单号、金额一致；伪造或错签通知不入账。
- [ ] 断通知后页面轮询 / 主动查单能补账，且同一订单只入账一次。
- [ ] 入账事务同时产生实付现金流水和官价额度包；客户余额与财务账本一致。
- [ ] 支付渠道手续费不抵扣客户额度；面板余额显示两位小数，精确账本保留。

## 3. Key 与首次调用

- [ ] 付款后客户能在密钥页创建付费 Key，限定模型、消费上限和并发数。
- [ ] `GET /v1/models` 只返回该 Key 获准且已上线的模型。
- [ ] `POST /v1/chat/completions` 非流式和流式各成功一次；工具调用、缓存命中和错误路径按已开放能力抽查。
- [ ] Key 上限、账户余额、并发与 TPM 限制在真实调用中生效；超额调用不产生上游费用。
- [ ] 上游无 usage 的响应保留预占、等待对账，24 小时释放；不按估计值扣客户钱。
- [ ] 调用记录有官方价格快照、Token、费用、剩余额度；按官价扣费，购包折扣不改变单价。
- [ ] 红优先扣减：先扣实付红条，红用尽后再扣赠送绿条；跨多个包按购买时间 FIFO。

## 4. 退款（红绿模型）

- [ ] 退款报价等于红剩余 `C − U`，手续费为 0；绿剩余整条收回并关包。
- [ ] 已申请(requested)或已开具(issued)销项发票时拒绝自助退款；红冲/作废后恢复可退。
- [ ] 账户存在在途调用时拒绝退款，提示先结算。
- [ ] 对公转账订单不显示自助原路退，明确提示联系财务人工处理。
- [ ] 真实渠道小额退款成功：客户收到原路退款，绿额度回收，账本、额度包状态和支付订单状态一致。
- [ ] 渠道明确拒绝退款时恢复冻结前的红绿额度；超时/结果未知按处理中冻结，不重复退款。
- [ ] 重复退款请求使用同一幂等键只产生一次资金效果。
- [ ] 退款后已消耗的那部分实付仍保留在可开票额度中；绿赠送不再可开票。
- [ ] 历史 15% 手续费退款记录保持原样，不套用新规则。

## 5. 发票与对账

- [ ] 充值即可按实付价格申请开票；未开票账户可退红剩余。
- [ ] 开票申请进入 requested 后立刻锁定该账户退款；红冲/作废后解锁。
- [ ] 可开票金额 = 累计实付 − 已退款 − 已申请/已开具发票。
- [ ] 付款后 30 天内开票的承诺已在页面写明；当前仅文案校验，人工确认无超期争议。
- [ ] 支付宝/微信账单费用按真实商户账单登记，未核对显示待核对，不猜零成本。
- [ ] 经营收益扣除已核对渠道费；客户预存资金与经营成本分账呈现。

## 6. 放量、监控与回滚

- [ ] 验收全程使用内部白名单账号，不创建真实客户订单或对外宣传已开放。
- [ ] 监控支付通知失败、退款处理中、调用结算失败、余额不一致和 429/402/5xx 错误。
- [ ] 核对 `/api/status` 的 `payments_enabled`、`inference_enabled` 与当前放量范围一致；`business_ready` 不误导用户。
- [ ] 通过验收后再按变更流程设置 `CUSTOMER_PAID_ENABLED=true` 和已验收的 `CUSTOMER_PAID_MODELS` 白名单。
- [ ] 放量首批只放白名单邮箱/小面额，观察一个完整账期后再扩量。
- [ ] 回滚演练：关闭付费开关 → 切回旧镜像 → 保留新表和数据 → 余额与账本未被改写。

## 7. 签署

- [ ] 负责人确认价格、授权、红绿退款与开票政策。
- [ ] 财务确认收款、渠道费、退款与发票账本一致。
- [ ] 技术确认验签、幂等、并发、用量结算与回滚。
- [ ] 供应确认模型可售、容量与质量证据有效。
- [ ] 验收证据（交易号、时间、金额、账单截图）保存在受控业务目录，不写入公开仓库。
