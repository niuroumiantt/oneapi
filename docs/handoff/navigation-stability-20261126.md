# 页面切换稳定性（2026-11-26）

## 范围与原因

用户反馈点击页面有延迟、加载晃动。基于 origin/main 32f56d3 隔离实现，未改动主工作区的未推送工作。

- 个人页每次切换都会重新等待账单、试用、员工额度和付费额度四组请求。
- 页面内容通过不同 `:has()` 规则改变共享侧栏、页眉和内容区尺寸；图表在 hashchange 时提前删除，使旧概览先变形再切页。

## 实现

- `web/navigation-data.js`：独立的导航读取模块，15 秒内存缓存，同账户共享进行中的请求。失败不缓存；按账户隔离；版本标记阻止被清空后的迟到请求回填。
- 仅工作台导航读取复用数据。实际生成 Key 的额度/模型权限检查仍直接请求 API，所有写入前后、401 均清空导航缓存。
- 首次/过期请求立即显示目标标题及加载状态；切换路由重置内容滚动，同页刷新继续保留滚动。
- `site-header.css` 统一个人页的侧栏、页眉、内容边距；删除页面分散的间距覆盖。嵌入工具保留自身内边距。
- 图表离开时停止请求/提示更新，旧内容交给路由整体替换，避免提前坍塌。

## 验证

- 42 项 UI、导航读取、模型 Key 流程回归通过；JS 语法和 git diff --check 通过。
- 本地模拟四个接口分别延迟 450/900/1800/600ms。改前概览→模型：1844ms 才切页，侧栏下移10px且内容间距变化两次。改后缓存有效时概览/模型/账单约26–42ms完成，侧栏和内容框架坐标保持一致。这是本地模拟测量，不是公网速度保证。
- Chrome 1366×768：概览内容643px，滚动高度643px；390×844：无横向页面溢出。首次加载显示目标标题，侧栏/页眉保持一致。
- 没有创建真实生产 Key 或进行付款。
