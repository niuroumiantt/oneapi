# 个人流程收尾、加载修复与新人指南 · 2026-11-26

## 用户要求与修正

检查个人注册、登录、充值、退款以及工作台加载延迟，制作一页新人 Flyer。截图问题为 API 对比先显示完整表单，再变为充值提示。用户随后明确纠正 Flyer 额度条：**左蓝赠送、右红实付**，与页面一致。

## 修复

- 对比页首屏先显示「正在检查可用额度」，服务器校验完成后一次进入表单、登录/充值提示或错误状态；失败不会显示可操作的残缺表单。
- 配置请求禁止缓存、12 秒超时；网络/服务错误提供「重新加载」。401/402/403 不误当成网络错误。
- 个人对比入口不再先等 billing、pilot、employee-credit、customer-credit 四组无关数据；对比接口仍独立检查实时额度和权限。
- 其他个人仪表页四组独立数据并行读取；旧路由响应在写入页面状态前检查 generation，避免快速切页时污染后续页面。
- 未改变账户余额、计费、权限、退款政策或支付逻辑。

## 流程核对

| 环节 | 当前行为及检查 |
| --- | --- |
| 注册/登录 | 公开 auth-methods：邮箱注册/密码登录/找回密码、手机验证码注册/登录、手机密码均启用；微信和支付宝不是登录方式。邮箱必须验证。隔离测试验证邮箱、会话隔离、CSRF、权限与恢复流程。公网既有验收会话未退出。 |
| 充值 | 核对金额与赠送后创建订单；只在签名/金额/商户校验通过后入账，重复回调不重复增加余额。付款页每 3 秒查询，最多 400 次，离开付款页停止；可手动查询。 |
| 模型/Key | 收藏不等于授权。专属 Key 仅指定模型，通用 Key 可在生成前删除不需要的模型。新 Key 必须有可分配额度；调整上限不充值。 |
| 用量/账单 | 模型、Key、调用明细对应计费记录；充值历史与消费记录分开分页，失败可重试。 |
| 退款 | 逐充值单核对可退实付；实付优先消费，赠送不能退现金；激活款/开票/约定限制由后台规则约束。待结算调用阻止退款；失败逆转冻结额度，重复请求幂等。 |
| 对比 | 平台额度自动读取；未充值显示充值入口，服务错误显示重试；第三方 Key 不持久保存，双侧分别计费。 |
| 支持/设置/VIP | 页面入口与返回正常，设置在底部，VIP 最后一项默认材料介绍。 |

## 验证与边界

- 公网修复前账单 → API 对比 → 充值提示，单次 UI 等待测得 1879 ms；包含浏览器自动化开销，不作为服务 SLA。
- 本地 4191 给 config 人为延迟 3 秒：加载时不显示表单；402 正确转充值提示；503 提供重试，恢复后点击重试成功进入可用表单。
- 1512×722 浏览器：页面总高 722，无外层滚动；对比 iframe 高 597。概览、模型、密钥、用量、充值、支持、设置、VIP 跳转通过。
- 10 项前端回归通过：并行读取、旧响应隔离、对比不等待无关数据、成功/401/402/503/超时状态、iframe 切换、分页等。
- 临时独立 PostgreSQL 55519：`journey_test`、`journey_refund_test`。77 项身份/支付/退款/账单/支持测试通过，无跳过。测试使用邮件和支付替身，不执行真实财务交易。
- 三个旧测试预期同步现行规则：支付宝返回用查询参数避免丢失 hash；满分配 Key 需先降额度才可创建新 Key；实付优先账本扣额与按购买比例计算的成本分别断言。服务端源码未变。
- PDF 一页 A4、嵌入中文字体、带注册链接二维码及可点击支持/对比/VIP 链接；Poppler 渲染目视检查，左蓝右红已按用户反馈修正。
- 设计检查提示旧 compare-context 边距、旧页面 glow；个人模式已有对应隐藏/覆盖，未扩大到重做全站设计。
