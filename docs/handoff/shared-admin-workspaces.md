# 公网业务与技术工作台整合

2026-11-10。用户批准双工作台分工，并明确授权本会话接管 openapi 本机 8800 另一窗口的未提交工作。

## 实现

- 业务 `/api/staff/workspace/console`：总览、供应采购、验收结果、商品上架、客户资金。复用既有采购资料、商品/价格复核及客户权限模块。
- 技术 `/api/staff/lab/console`：五组导航，统一 Key 输入；探测、型号/费率、测试/对比、计量核对、交付与目录发布。公司身份认证在服务端校验，额外技术授权通过 `staff_technical_access` 管理；platform_admin 可访问两边。普通企业 owner / 客户身份不授予平台权限。
- canonical `suppliers` 为业务主档；原 `supplier_lab_suppliers` 保留为历史关联，增加 canonical_supplier_id。旧建供应商接口返回 410；不删除历史表、Key 或记录。
- 技术型号自动关联供应产品；测试任务、型号和账单核对作为验收报告引用，业务读取同一份结果。四题只验基础能力和计量抽样，不证明模型身份/容量/SLA。
- 上架先通过既有采购资料、真实报告、商品复核、价格批准；业务提出目录发布申请，技术发布。证据快照变化或 Key 停用时公开目录自动隐藏，原记录保留。**目录发布不开放正式付费调用**。
- 新迁移 `022_shared_workspaces.sql` 仅新增表、列、索引和关联。不删除旧表。数据库回滚应恢复旧应用，保留新增结构。
- 本机 openapi `/admin/upstreams` 改为跳转同一公网技术台；旧 POST 返回 410，删除重复输入页面和存储代码；原 managed-upstreams.json 保留作迁移备份且不再自动加载。
- 运维是已定义的应用动作，未添加任意命令终端或 Docker 控制接口。

## 凭据迁入

`server/import-local-upstreams.mjs` 只从 stdin 接收本机已有 JSON，通过服务器配置的 vault 加密并原子写入，按主机+指纹防重复。不得把 JSON、Key 或配置文件内容输出到聊天/日志/Git。候选型号迁入时价格为空，历史本机“通过”不冒充服务器验收结论。脚本不发起上游调用。

## 验证

公网测试 29 项，本机网关 23 项。隔离浏览器逐页检查业务 5 页、技术 10 页，1440×900 下整页不溢出、无 JS 错误；长表在工作区内滚动。界面测试使用明显的测试数据；真实身份、Key、计量交付及发布门槛由隔离数据库集成测试覆盖。

## 仍需业务完成

KerAPI 采购合同、主体、费率、原厂版本证据、真实测试和账单对账完成前不能销售。当前公开推理仅已有试点；新目录发布没有自动改变试点路由。统一 SSO 与客户邮箱登录仍为两种会话，公开账号菜单提供平台员工入口，不按邮箱字符串自动提升权限。
