# 个人充值与账单精简 · 2026-11-26

## 用户要求与状态

充值、余额和消费账单关系清楚；必要信息和操作，精简干净，一页高度、不滚动。
本轮完成代码与本地模拟预览，尚未部署公网。当前公网版本的已验证记录仍见 personal-settings-20261126.md；不要将本轮预览当成线上更新。

## 实现

- 顶部额度余额，下方实付与赠送剩余；充值增加额度，调用按模型官网价扣减。
- 三个互斥视图：充值、消费账单、充值记录。充值保留金额、常用金额、选填促销码、可用付款渠道，先核对实付/赠送/到账再付款，成功后回到已选模型或通用 Key 接入；原报价确认、优惠退款条款、幂等订单、付款轮询沿用。
- 消费账单按每次已结算调用列出模型、Key、时间、扣减额度和实付费用，每页 3 条。小于一分钱的额度保留小数，极小值提示小于 ¥0.000001。
- 实付费用来自 credit_consumptions.cash_fen。额度与现金按分累计结算的差值不能直接称为赠送，因此不显示单次调用的“赠送消耗”推算值。纯赠送消费仍会显示，实付为 0。
- 充值记录每页 3 条，显示原到账时实付、赠送与到账额度，区分当前余额。退款和发票是右上次要入口；退款每页 1 笔并复用原退款校验/进度，发票表单与开票记录分开，每页 2 条（接口仍返回最近 50 条）。
- 新增只读 GET /api/billing/personal/records?kind=usage|recharge|refund&page=0。服务端按登录用户 owner_id 隔离，LIMIT+1 分页，不依赖旧账单快照 50/100 条上限。退款记录在分页后调用 refundQuote，保留开票/VIP/特殊优惠限制。
- 企业账务走原分支。本次没有修改扣费、支付回调、退款或发票入账逻辑，也没有数据库迁移。
- 新子视图使用 data-billing-view，避免与站点全局 data-view 路由冲突；异步记录缓存属于当前页面实例。
