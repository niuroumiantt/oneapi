# 微信交易账单自动核对

2026-11-15，m5。复用商务后台「收款与退款」及「经营损益」，不开放微信付款入口。

- 账单客户端独立于 WECHATPAY_ENABLED/AppID。证书和公钥已配置时可以获取交易账单；客户支付仍由原开关控制。
- APIv3 签名申请 ALL 账单、验证响应签名；下载仅允许官方固定 HTTPS 主机和路径，签名请求、拒绝跳转、限制 16 MiB，并按已验签响应中的 SHA1 校验原始文件。下载流本身无响应签名，不能按普通 JSON 响应验签。
- CSV 按表头和反引号解析，核对商户、日期、币种、汇总笔数与金额。未知格式、精度或缺失汇总不入账。
- 普通收款手续费为正，退款退费为负。按微信交易号/商户单号/退款请求号/金额/状态核对，按唯一流水保存成本分项，订单保留净渠道费。重复同步不累加，不重复费用版本或审计。
- 退款账单按受理日出账，账单里的 PROCESSING 状态不会更新；重试时用已验签的单笔退款查询刷新该状态，同时仍要求本地退款已成功。未知退款、缺单、金额差异留人工核对，不用账单变更客户余额或退款状态。
- 成本视图按费用账单日期汇总，跨月退费在退款月份冲减成本；支付宝及手工费用维持原口径。手工修正优先，不被自动覆盖。
- 北京时间 10 点后每小时检查，六小时重试，近期七天复查；最长回查 90 天，每轮八天。跨进程 advisory lock 防止同时同步。无本地交易不自动造账；可手动同步指定日期。
- 页面展示最近七份账单、待重试/差异、非本站交易忽略数量；订单仍显示具体差异和原有手工费用入口。不保存原始账单、临时下载地址、OpenID 等非本站客户信息。
- 增量迁移 064：wechat_bill_days、wechat_bill_entries、payment_channel_costs 视图。回滚应用可保留这些增量结构，微信入口继续关闭。

验证：独立临时 PostgreSQL 全套 96 项；涵盖跨月费用冲减、重复同步、金额和符号异常、手工修正保护、客户账本不变、付款关闭时账单可用；Chrome 本地虚构数据检查现有页面、微信同步弹窗与差异记录，无页面横向溢出。

生产边界：目前没有本站微信实收和退款，不将模拟账单写入生产。首笔真实收款/退款及次日账单的端到端验收，待服务号审核和绑定完成后进行。
