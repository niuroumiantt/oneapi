# 供应商与供应商产品管理

版本 0.3，2026-11-06。供应管理升级为首期第五条并行主线，与登录、模型/Agent、支付、促销共同交付。本文是设计及官方资料核验，尚未签约采购、充值上游、接入真实凭据或执行压力/故障测试。

## 1. 业务目标与边界

本模块负责获得获准的模型服务、建立采购产品、控制采购成本和可售能力、管理容量与需求、观察质量和故障、处理供应对账与续约。供应商自助入驻可以后置，但平台自己管理供应商与产品必须首期具备。

客户广场回答“客户能买什么、怎样接入”；供应中心回答“从谁采购、按什么条件交付、还剩多少资源、目前能否可靠服务、实际成本多少”。同一客户商品可映射多个获准采购方案，前台型号不因后台增加渠道而重复成多张同名卡片。

## 2. 如何获得上游资源

| 来源 | 首期做法 | 必须确认 |
| --- | --- | --- |
| 模型官方标准 API/企业服务 | 从 DeepSeek、智谱对应地区官方入口申请，建立平台自己的采购账户；按实际业务申请扩容或商务方案 | 实际法人、服务条款、平台集成/销售范围、可售地区、价格、账单、数据路径和支持 |
| 获授权代理或托管/云服务商 | 用于价格、区域、容量或备援有具体价值的方案；逐项核验来源 | 上游授权链、真实模型与版本、是否允许我方服务模式、计量、处理路径和故障依赖 |
| 自部署模型 | 保留为未来独立供应方式 | 模型许可证、算力与运营成本、部署能力和质量承诺；首期不为此扩建推理集群 |

公开零售 API 开通只证明取得相应调用能力，不自动证明已获批量折扣、转售/下级分销授权或合同 SLA。个人 Coding Plan、共享账号与来源不明 Key 不作为未经授权的采购渠道；客户永远使用平台自己的 Key。[G10](06-sources.md#models)[G11](06-sources.md#models)

对供方的标准询价清单：我方主体和用途；销售地区与客户类型；计划接入型号/版本/协议；预计日用量、输入输出比例、缓存比例和峰值并发；单价与阶梯/时段规则；最低消费或承诺量；充值/账期与退款条件；速率和扩容；可写入合同的质量指标；数据处理/留存；账单证据；故障联络和变更通知。

实际入口从官方开始：DeepSeek 开放平台、官方文档中的支持邮箱及扩容申请；智谱 BigModel 控制台的账户速率、扩容申请、财务和人工支持。国际供应分别核实实际账户与合同。后台记录联系来源、询价状态、负责人、下次跟进时间与报价有效期；本轮仅整理流程，没有向任何供方发出询价。[SUP01](06-sources.md#suppliers)[SUP07](06-sources.md#suppliers)[SUP09](06-sources.md#suppliers)

无需先虚构需求数字。尚无真实客户流量时把需求标为试运营估计，先用小额、受限的获准服务获得证据，再谈承诺量和长期采购。试用、充值或签约是实施动作，本轮未执行。

## 3. 一家供应商可以提供多种采购产品

| 对象 | 清楚表达的业务含义 | 关键关联 |
| --- | --- | --- |
| Supplier | 我们向谁购买、由谁负责服务 | 法人、联系人、支持、风险与审查证据 |
| SupplierContract | 按什么协议购买和使用 | 授权、期限、地区、结算、SLA/通知条款 |
| SupplierAccount | 实际计费和限额所属采购账户 | 区域、凭据引用、余额/资源包与官方账户标识 |
| SupplierModelOffer | 供方的一项可采购模型服务 | 模型版本、能力、协议、合同、成本版本与销售范围 |
| ProviderEndpoint | 请求真正发往哪里 | 地址、数据路径、采购账户、故障域与健康 |
| SupplyCapacityPool | 哪些通道共用同一实际限额或保留容量 | 供方定义的账户/模型/区域等作用域、容量、已用与预留 |
| SupplierRateCardVersion | 特定时间有效的采购计价规则 | 币种、单位、维度、阶梯、时段与生效规则 |
| SupplierCostEntry | 每次实际尝试对应的采购成本证据 | ProviderAttempt、原始/标准化 usage、暂估/确认状态与更正 |
| SupplierBill / SupplierPayment | 供应商如何出账、我们如何付款 | 账期、币种、账单行、支付凭证、差异和更正 |

沿用现有 ModelFamily、ModelRelease、ModelProduct 和 ProviderAttempt。新对象是职责边界，不要求每个对象变成独立服务。凭据与余额不直接挂在模型家族上。容量池按供方实际作用域建立：同一账户、同一模型共用限额的多个 Key 关联同一池；同账户不同模型可能各有池，并同时受账户总限额约束。采购资金/资源包另按实际账户、币种与适用范围汇总，不把所有资源硬合成一个池。

供应商产品卡至少展示：品牌与真实版本、支持协议、输入/输出模态、工具和思考能力、上下文与输出限制、允许销售地区、数据处理条件、采购价版本、结算方式、额度/并发作用域、批准状态、健康与最后核验时间。

## 4. 从候选到生产的准入流程

发现来源 → 初步询价/资料 → 合同及授权核实 → 建采购账户与产品草稿 → 受限测试 → 核对计量和账单 → 小流量试运营 → 批准生产 → 持续评价/续约/退出。

测试覆盖两家族的实际版本、流式、Agent 工具循环、思考参数、上下文限制、用量、错误和数据路径；型号自报身份不是来源证明。测试材料采用受控样例，不把真实客户提示词任意发给新的候选供应商。

每个首发家族至少有一条获准且经过验证的供应路径。争取真实独立的备用路径，但不能把同一供方的两个 Key、同一底层服务的两个经销商算成双重冗余。只有单源时可在明确限制下试运营，不能据此承诺已具备自动高可用备援。

## 5. 采购价、客户售价和佣金分别管理

采购成本规则需要记录：币种、税口径、每百万 token/每次/时长等单位、未命中输入、缓存命中、缓存写入/存储、输出、推理、附加工具、长上下文阶梯、峰谷时段、最低承诺、有效期及舍入方式。不存在的收费维度不凭空添加。

分别保存公开报价、已签协议价、当前适用阶梯、待满足条件的采购返利与最终账单成本。报价有来源和有效期；未实现返利只用于情景测算，不提前抵减确定成本。询价比较在相同模型/能力、地区、用量结构和税币口径下进行，不单看一个最低输入价。

仅将互斥的计费项相加。若缓存命中已包含在输入总量中，先拆分再计费；若推理用量已包含输出，不重复收费。资源包按供方实际扣减顺序、适用模型和有效期估算，不能把所有 token 当成等价资源。

示意公式：采购成本 = 非缓存输入量×对应单价 + 缓存输入量×对应单价 + 输出量×对应单价 + 实际适用的其他费用。金额采用明确精度，不使用二进制浮点累积。官方当前时段、usage 与资源包规则见 [SUP01–SUP10](06-sources.md#suppliers)；真实费率以实际合同和当期资料为准。

每次 ProviderAttempt 保存采购方案、费率版本、计费时间依据、币种、实际使用、供方请求标识及成本状态。供应成本区分预计、使用量确认、账单对账确认；如果供方按不同于请求发起时刻的时点计价，保留对应时间和差异，不假定客户界面时区决定采购成本。

客户价格由 PriceSnapshot 固定，促销和佣金按自己的规则执行。同一客户请求的供应成本应汇总所有实际尝试；重试、健康探测、错误调用等由相应成本中心承担，不能遗漏失败尝试或把平台探测费用扣到客户账户。

客户退款不自动消除已产生的上游成本。供方退款、折让或 SLA 补偿另外关联原采购记录。上游充值是供应预付及资金动作，使用成本单独归集；正式会计科目由对应主体财务确定。

## 6. 量、需求与采购资金

至少分开四类资源：

- 资金/信用：现金预付、赠送金、账期额度、已确认应付和可支配余额。
- 消费权益：资源包、token/次数/时长、适用型号、到期与扣减顺序。
- 瞬时容量：并发、RPM/QPS、TPM 及供方定义的作用域。
- 已承诺容量：供方明确保留的能力、平台已向客户承诺的能力与实际可分配余量。

DeepSeek 官方按账户和模型管理并发，同一账户换 Key 不增加总容量；因此容量池不能以 Key 数量推算。公开余额接口区分赠送与充值余额，但余额充足也不保证并发或服务健康。[SUP01](06-sources.md#suppliers)[SUP02](06-sources.md#suppliers)

建立 model + region + supplier_pool 粒度的需求视图：请求量、输入/输出用量与比例、缓存比例、峰值并发、排队、增长、活动预测和客户承诺。按日/周比较预测与实际；明确样本和置信程度，不将促销报名人数直接视为必然使用量。

在稳定平均条件下，可用“每秒到达请求数×平均请求时长”粗估平均并发。例如每分钟 600 次、平均 20 秒，约为 200 个并发连接；真实容量还需看峰值、长尾、token 限额、路由与可用余量。这只是规划例子，不是平台容量声明。

采购余额覆盖天数按近期日成本、预测活动及在途消耗估算，展示价格/汇率、数据时间和估计范围。赠送金/资源包到期、余额过低、合同到期、限额接近阈值时分别告警。没有可靠查询接口时显示“人工更新/待同步”和时间，不伪造实时余额。

DeepSeek 可规划基于正式余额 API 的同步。智谱已核实控制台财务查询与账单下载，本轮未确认标准 API 的公开余额/全账户账单接口，首期允许人工快照和官方账单文件导入。智谱适用资源包先于现金扣减，同场景优先消耗较早到期者；需按产品权益判断是否仍可服务，不能仅凭现金余额把所有有有效资源包的产品一并停掉。[SUP02](06-sources.md#suppliers)[SUP09](06-sources.md#suppliers)

首期用余额/容量预警、采购建议和人工批准充值/扩容。后续自动采购需要单独定义授权金额、价格范围与重试规则。多个外观不同的供应渠道若共享故障域或容量池，汇总计算集中度和备用能力。

## 7. 质量与稳定性监控

| 维度 | 观察内容 | 用途 |
| --- | --- | --- |
| 连通与权限 | DNS/TLS/连接、鉴权、模型权限、余额异常 | 区分接不上、无权限、欠费和模型不存在 |
| 有效完成 | 合法上游请求的有效完成率、HTTP 与业务错误、流中断 | HTTP 200 或连接存活本身不证明结果完整 |
| 延迟与速度 | 首个有效内容时延 p50/p95、完整耗时、输出速度中位数/低分位 | 不能把心跳/空白当首 token；同类任务比较 |
| 容量压力 | 429 分类、并发占用、RPM/TPM、排队时间、过载 | 决定扩容、排队和限流 |
| 能力与输出 | 工具完整循环、结构化格式、视觉等承诺能力、固定任务样例 | 发现版本变化和能力回退，避免只比较通断 |
| 计量与成本 | usage 完整率、重试成本、采购预估与账单差异 | 发现漏报、错价、计量不一致和负贡献 |

指标带窗口、样本量和分母。将客户参数错误、内容拒绝、主动取消、平台拒绝和真实上游故障分别展示；不通过删除失败类别美化健康。请求级客户成功率与尝试级供方成功率分别统计；备用路由挽救了客户请求，也不能抹掉主通道失败。

结合真实流量的被动监控、受限合成探测和供方状态公告。探测有预算及频率限制，费用归平台监控成本；低流量或数据过期时标未知，不因没有错误样本而显示高质量。官方状态页只是证据之一，不能代替我们本地区、本账户、本型号的真实指标。[SUP04](06-sources.md#suppliers)

分别处理网络连接超时、首次有效内容超时、流中间停顿与总任务期限。上游心跳可能维持连接，但用户仍未收到有用结果；具体模型排队机制与客户端容忍时限需要独立验收。[SUP01](06-sources.md#suppliers)

## 8. 五类状态独立，故障有明确处理

| 状态维度 | 例子 | 对路由的影响 |
| --- | --- | --- |
| 商业资格/产品发布 | 草稿、测试、获准、暂停、到期、退役 | 未获准或过期不能生产调用 |
| 凭据 | 有效、轮换中、失效、吊销 | 只用有效凭据，轮换和吊销有生效证据 |
| 资金/权益 | 充足、预警、耗尽、待核实 | 余额与适用资源不足时停止相应新增请求 |
| 容量 | 充裕、接近阈值、受限、不可分配 | 受控排队、限流或选择其他合格池 |
| 运行健康 | 健康、降级、不可用、未知；另有熔断/试探恢复状态 | 调整权重、熔断、受限探测，确认后渐进恢复 |

商业获准不代表当前健康；一次性能故障也不自动撤销商业协议。管理员看到各项原始状态及原因，综合可路由结论由明确政策计算。

错误必须按 provider + HTTP status + 业务错误码 + 当前阶段分类：权限失败核实凭据；余额问题触发采购；容量限制尊重 Retry-After（如提供）并退避/限流；服务过载按健康规则熔断；参数和内容类错误不盲目重试。智谱官方业务错误码存在相同 HTTP 429 下不同原因的情况，不能用一个通用 429 重试规则代替分类。[SUP06](06-sources.md#suppliers)

例如智谱 1113 表示欠费，1302 表示账户速率限制，1305 表示平台过载，三者均可能使用 HTTP 429；处理应分别面向资金/适用权益、容量调度和供应健康。DeepSeek 的 402 余额不足与 429 限流也须区别处理。[SUP03](06-sources.md#suppliers)[SUP06](06-sources.md#suppliers)

健康规则基于滑动窗口、最低样本、连续异常及恢复证据，阈值按首批流量设定。恢复不是一次探测成功就全量切回，而是受限试探、观察、逐步增量；记录异常起止、影响、操作人、供方工单、补偿和后续动作。

## 9. 备用路由的实际边界

每次选择都同时满足地区/数据授权、客户合同、真实模型版本与所需能力、协议、采购预算、容量及健康条件。优先提供固定供应或同模型的获准备援；跨家族、低能力替换及跨区默认不自动发生，按客户明确允许的方案执行。

合格备用复用模型接入模块的 CompatibilityCheck：客户端形态/版本、模式、地区、实际模型/供应版本、适配器与能力都在有效验证范围内。同模型名和同协议不能自动继承主通道的 Agent 已验证标签。

流式内容尚未交付且执行状态与重试条件允许时，才能按规则重试/换通道。已经交付部分内容后不把另一个模型的新回答无提示拼接进去。超时导致上游是否执行不明时保存未决尝试，采用受限、可计成本的处理策略，不能承诺跨供应商恰好执行一次。

每次尝试都有 attempt_id、供方请求标识、状态、成本与原因，重试有次数、时间和费用上限。整个链路失败时向客户给出稳定错误和请求 ID，记录待对账事项。

备用通道成本更高时，在已公布的客户价格与服务条款内处理，不在同一请求中临时加价。采购、促销和路由共同检查贡献空间；暂停新促销/新售卖与已领取权益和已开始服务分别处理。没有合格备用时明确失败或限制销售，不编造高可用。

## 10. 采购对账与持续供应

每日或约定账期核对：平台实际尝试/usage → 按采购规则估算 → 供方账单/资源扣减 → 我方充值付款/账期应付。供方账单导入有来源、账期、币种、唯一键及文件指纹，重复导入不重复产生应付或成本。

差异分类为时间窗、缓存/推理含义、重复尝试、费用版本、资源包优先级、最低承诺、汇率/税、补偿或遗漏。供方只给汇总账单时按实际粒度对账，不声称已经逐请求匹配；保留未分配差额并跟进。

供应经理定期检查合同/授权到期、模型下线、价格和限额变化、资源包到期、数据路径变化、集中度、未解决事故及联系人有效性。模型别名或处理地点变化触发相关商品与 Agent 配置重新验证。供应商退出时停止新路由、结清未决费用并保留必要凭证。

## 11. 首期后台布局

- 供应总览：当前受影响模型、资金/容量预警、熔断通道、到期授权、待对账差异；可直接定位负责人和下一动作。
- 供应商档案：主体、合同、联系人、来源证据、地区与续约。
- 供应产品表：型号/实际版本、协议、成本版本、可售地区、能力及发布状态。
- 账户与资源：现金/赠送/资源包、到期、更新时间、共享容量池和预算。
- 通道与质量：错误分类、延迟、速度、样本、健康、熔断及真实依赖。
- 采购与对账：采购申请、付款、供方账单、差额和审批凭证。

沿用高密度表格与侧边详情。供应经理可管理产品和资料，财务管理付款/对账，运维处理健康与事故；敏感凭据只提供受控轮换入口。运行状态和后台审批共用现有审计、通知、账本与网关能力，不另造完整 ERP。

## 12. 与其他四条主线的连接

模型广场只上架获准且有价格、能力和供应依据的商品；接入向导读取该供给实际支持的协议与能力。支付模块提供客户资金，供应模块另外观察采购资金，分别记账。采购成本用于活动准入和贡献核算；佣金仍依照已收款且实际消费的合格净服务金额与规则快照计算，供方后补账单或成本调整不自动追溯改变客户费用和已成立佣金。身份系统控制员工采购/审核范围与客户预算。

五条线并行开发。供应侧最早给出首批真实 offer、凭据产品类型、能力、价格、容量与错误分类，作为模型接入和成本测试的输入；界面与共享接口可以同时开发。

## 13. 首期验收

1. 两家族各一项获准供应产品，有真实账户、条款、价格版本、容量范围和测试证据。
2. 多 Key 按供方实际账户/模型限额作用域共享容量，资金与资源包另按实际账户汇总；不重复销售容量，可识别相关故障域。
3. 欠费、Key 失效、平台过载、并发限额分别触发正确处置，不无限重试。
4. HTTP 200 后流中断、只有心跳和迟迟无内容能够被识别；不误报成功。
5. 主通道故障时，只在可接受条件下进入合格备用；没有备用时可解释地失败。
6. 两次真实上游尝试的成本均保留，客户费用符合规则；健康探测不扣客户余额。
7. 资源包到期、价格时段切换、余额数据过期和合同到期分别验证；不能沿用失效权益。
8. 采购预估、实际 usage、供方账单与付款可追踪；重复导入不重复记账，汇总差异有人负责。
9. 更高采购成本不倒改历史客户价格、促销或佣金；审批记录可追溯。
10. 凭据轮换、供应暂停、供应恢复与退出不会绕过地区、授权或预算边界。
