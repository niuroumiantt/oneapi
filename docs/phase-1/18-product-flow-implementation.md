# 首轮产品链路：已落地页面与实施顺序

2026-11-07。此文记录当前代码能力；除客户与员工身份外，交易与调用仍是隔离演示。`/api/status` 的 `payments_enabled`、`inference_enabled` 继续为 `false`。

## 已落地

| 环节 | 页面与接口 | 当前行为 |
| --- | --- | --- |
| 供应与验收 | 内部 `#ops/supply`、供应商/型号/证据/测试/验收接口 | 仅员工可见；供应商进度、七项资料、成组测试、验收结果、阻断状态持久保存 |
| 商品设计 | 内部 `#ops/products`、`model_products`、商品资料接口 | 可建供应型号或 semifly.ai 自有服务草稿；记录品牌、家族、版本、用途、能力和限制；无发布开关 |
| 价格与复核 | 内部价格草稿、独立复核 | 价格版本有证据链接；供应型号需资料与验收后才可申请复核；自有服务需另建真实交付验收，不以内部草稿替代 |
| 客户选购 | 个人与企业 `#demo/...` | 多选演示型号；充值单与型号解耦，¥5 起；模拟付款后余额供已授权型号共用 |
| 企业分配 | 企业模拟体验台 | 代表人逐员工设置人民币模拟额度及允许型号；员工只能使用自己获准的型号；变更与使用有校验 |
| 接入、用量与退款 | 模拟接入、模拟调用、`demo_ledger`、模拟退款 | 按所选型号计量扣减，保留订单、流水、退款来源；退款仅冲减未用模拟实付余额，不产生真实资金或手续费 |
| 促销 | 内部 `#ops/promotions` | 可绑定价格草稿保存活动、折扣和预算草稿；不发码、不兑换、不计佣 |

模型广场目前展示**明确标注的品牌与型号演示卡**，不是从真实供应密钥发现的商品。真实商品对公众继续关闭；自有服务不能仅改名便称为自研基础模型。上游 Key 没有接收接口，不能填入备注、数据库字段或演示接入。

## 接下来的实施顺序

1. **供应账户与凭据**：取得合同、转售授权、型号清单、采购价和测试 Key；在受限运维环境接通 KMS 凭据、最小权限、轮换与审计，再按真实供给进行自动探测和计量核对。
2. **商品发布与真实目录**：为每个型号补全能力、限制、版本、性能与报价，建立技术、商业、价格三重批准及失效撤架；公开目录只读批准的版本。自有服务单独完成底层授权和交付验收。
3. **真实收款与资金账本**：接商户订单、验签回调、幂等入账、对账和原路退款；真实余额与 `demo_*` 永不混合。最低充值 ¥5；15% 退款手续费在法务、财务和支付渠道确认前不执行。
4. **统一调用网关**：发行只显示一次的平台 Key，限定客户、项目与型号；请求预留额度、验证供应健康、路由到上游、按返回计量结算，维护客户费用与采购成本双账。
5. **促销发布**：绑定已发布售价和真实消费事件，分开记实付本金、赠送权益、折扣和佣金，完成预算上限、反作弊、退费冲回与对账。

验收条件：完成每一环节的权限与隔离测试，生产侧能核对真实来源和资金，网页状态与 `/api/status` 一致；没有真实商户或供应资料时不以演示数据代替验收。
