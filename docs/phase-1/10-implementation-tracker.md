## 本轮可操作原型

- `/#login`：个人、企业、平台员工三入口，明确预览身份与真实认证边界。
- `/#personal`：独立个人工作区快照，余额不与企业混用。
- `/#enterprise`：企业 A 累计充值 ¥1,000；10 位成员预算各 ¥100，其中已消费 ¥286、在途 ¥5，未分配额为零。消费样例不是新扣款。
- 身份预览：企业所有者、企业管理员、研发部门管理员、财务、普通成员。切换是体验功能，不是生产授权。
- 成员管理：筛选/批量设置预算、调拨、暂停/恢复/移除；邀请只生成本标签页待加入草稿，不发送消息。
- 加额流程：普通成员提交申请；管理员在未分配额度内批准。资金不足时保留待处理状态，需要先回收可用预算。
- 其他页面：项目与 Key 示例、用量图表、企业资金、审批记录、权限说明。真实 Key、账单、付款及模型调用仍未接入。

所有原型状态只在内存中，刷新恢复。金额示例使用整数分；未来生产账本使用定点高精度金额，不能把本原型当生产计费引擎。浏览器角色模拟不是安全边界；不承诺本轮已验证数据库事务、网络并发或真实身份隔离。

## 已验证

纯规则测试覆盖：总资金守恒、不能超分配、转出不含消费/在途、批量全量校验、部门越权拒绝、财务与成员只读限制、移除保留历史、待加入成员零额度、重复审批拒绝、无效金额输入。

浏览器验证：合法 ¥40 调拨双方结果；¥66 超出可调 ¥65 时拦截；成员视图仅本人；部门视图仅本部门；加额申请留下记录；三类入口跳转；390px 窄屏重排且页面不横向溢出（成员表允许内部横滚）。

## 后端实施顺序

1. 冻结地区/身份/组织/项目/计费账户的共同标识与权限契约；选定并接入实际认证核心。
2. 供应档案与验证、商品发布、企业钱包与预算同步落地；支付和促销复用同一资金/用量事件。
3. 串联：登录 → 工作区 → 商品价格 → 充值 → Key → 真实调用 → 预占/结算 → 费用/权益/计佣。
4. 五模块验收通过后，按已定的公众注册方式开放真实业务。静态页面发布不等于业务开放。

真实外部条件：商户开通、OAuth 应用与恢复渠道、获准供应账户、具体销售商品/价格、促销比例仍需落实。秘密通过受控配置接入，不写入聊天、前端或 Git。
