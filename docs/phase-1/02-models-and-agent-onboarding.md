# 模型广场与 Agent 接入

版本 0.3，2026-11-06。用户提到 trail，本文暂按 TRAE 理解。官方资料支持的是接入可行性证据；本轮没有调用付费模型、安装客户端或完成真实兼容测试。

## 两家族入口，完整目录分层

首页只保留 DeepSeek 与智谱 GLM 两个家族入口。家族页先展示推荐型号，提供“全部型号”与用途筛选；专业能力和历史型号独立归档。当前目录见 [模型快照](05-model-catalog-snapshot.md)，不再沿用旧型号作为默认最新值。

初始推荐候选为 deepseek-flash、deepseek-v4-pro、glm-5.3、glm-5.3-flash、glm-5.3-flashx。是否首发取决于实际采购和端到端验收；两家族各至少一条完成真实闭环的路径即可启动受控试用，其余候选并行验证。

每张卡片先显示用户需要判断的事情：模型名称、适合任务、输入类型、可用地区、当前价格/促销价和适配状态。上下文上限、精确 API ID、协议和计量维度放入详情。上游文档的最大窗口不直接设为所有用户默认预算。

后台按完整目录登记能力；前台只对获准且验证过的商品显示可用操作。图像/视频/语音/向量等专业模型不默认显示“接入编程 Agent”。同一采购平台内的 Vidu 等第三方品牌不加入当前两个家族。

## 两种自然入口汇合

- 模型优先：模型广场 → 家族/型号 → “接入我的工具” → 选择 Agent。
- 工具优先：“我用什么工具？” → Cursor / TRAE / Qoder / WorkBuddy → 推荐该版本与地区适用模型。

未登录用户可先比较、选型号和输入活动码；真正创建 Key、领取账户权益或付款时再登录。通过 OnboardingIntent 恢复选择，避免授权返回首页后重新操作。

## 一键生成的是完整接入配置

用户选择 Agent、型号、地区、项目及预算。系统自动匹配接口协议、URL 拼接方式、模型 ID、能力开关与已知限制，签发平台自己的受限 Key。上游采购 Key 永不下发。

接入配置至少包含：工具与版本、模型名称和 API ID、本地区平台地址、认证方式、项目 Key、能力配置、价格/权益说明、客户端操作步骤及验证状态。

默认每个工具/项目生成专用 Key，权限限定所选模型；用户可明确增加其他模型。名称可以是“TRAE · 项目 A”。生成操作幂等，不因连点重复签发。Key 只在创建时完整显示，不进入链接、分享、分析事件或公开配置。

“生成配置”是平台可控制的动作；“导入客户端”只有官方存在对应导入能力且平台验证过才展示。没有该机制时提供逐字段复制与短步骤，不能把导入 MCP、Prompt 或规则的链接冒充大模型供应商配置导入。

## 三种协议分别维护

| 协议 | 平台拟公开路径示意 | 关键验证 |
| --- | --- | --- |
| Chat Completions | /v1/chat/completions | 消息格式、工具调用、流式 usage、推理字段 |
| Responses | /v1/responses | 输入/输出项、事件序列、工具输出、会话历史、存储和取消 |
| Anthropic Messages | /v1/messages | 认证/版本头、content blocks、thinking、tool_use/tool_result、流事件 |

路径是拟定平台契约，不是已经上线的端点。客户看到的是本平台域名；上游 URL、凭据产品类型和参数映射由适配层处理。优先使用已获准上游原生协议，再评估成熟网关的适配，不把三者当成改一下路径就能互换。

当前 DeepSeek Responses 无服务端会话存储，多轮需完整 input；智谱 Responses 默认 store=false、流结束不发 [DONE]、当前无 cancel。模型也有差异：GLM-5.3/Flash 系列不能关闭 thinking，DeepSeek Pro 不具备 Flash 的图片输入能力。模板按能力映射，不能统一硬编码一个参数集。[D4](06-sources.md#models)[G9](06-sources.md#models)[G2](06-sources.md#models)

## 接入向导四步

### 1 选择工具和模型

先显示四个工具入口，Qoder 再选桌面/IDE/CLI；版本信息可放在必要时展开的“查看我的版本”帮助中。自动过滤该地区供应、协议和能力不合适的组合，给出原因与可选方案。

### 2 确认账户与费用

显示当前工作区、项目、服务地区、模型、公开价、已领取专属价、余额及预算。促销码入口在此仍可用。账户没额度时可以先生成配置，清楚说明首次实际调用的资金条件；若未配置试用权益，不暗示免费。

### 3 生成并复制配置

主按钮“生成接入配置”，完成后按目标软件字段展示：API Key、接口地址、模型 ID、需要的选项。次按钮按真实能力显示“复制 Key”“复制地址”“复制模型 ID”“查看三步设置”；官方导入功能通过验收后才出现。

高级协议细节折叠。复制成功、Key 过期、额度不足、模型不在授权范围等状态给出清楚的下一步，不展示未经解释的内部实现细节。

### 4 完成首次客户端调用

平台连通测试先证明该配置可连接；再让客户在客户端完成一个简短任务。用专用 Key 的请求记录确认收到本次调用，显示模型、时间和已结算/预估费用。平台自测和客户真实客户端调用分别记录。

验证工具能力时必须看到模型发起工具、客户端执行、工具结果返回和模型继续回答；单次文本返回不算 Agent 工具功能通过。首次调用成功也不自动改变全平台兼容状态，兼容标签来自受控测试。

## 数据与维护

ModelProduct 与 SupplierModelOffer 管商品和地区采购；ModelCapability 管模态、工具、思考和限制；AgentConnectionProfile 管客户端形态/版本/套餐、协议、URL 模式、认证、模板和已知限制；CompatibilityCheck 管测试证据。

供应模块是本页的实时业务输入：每项可售商品至少对应一个获准采购方案，具备实际账户、价格版本、协议/能力、容量池和可用性证据。供应商数量增加不复制前台同名商品；新增或替换通道要保持该商品及客户端组合已承诺的版本、能力、地区和数据条件。没有合格供给时关闭新购买/配置激活并解释业务影响，已有 Key 保留身份但按当前可用性响应。详见 [供应商与供应产品管理](07-supplier-operations.md)。

适配状态为文档可配置、待验证、已验证、有条件支持、暂不支持。已验证必须标明客户端版本、模式、模型/供应版本、地区、能力和时间，不能只用 supports_cursor=true。

官方型号与价格变化进入待审同步记录，确认后发布；历史别名指向发生变化也要记录，不能静默替换客户选定的固定模型商品。模板与规则有版本，客户端升级后针对受影响的协议与功能做回归。

## 首期验证边界

覆盖认证与最终 URL、普通/流式、取消与超时、限流、多轮/并行工具、JSON 参数分片、thinking、图片/文件（若承诺）、Responses 会话行为、计量与成本、区域与预算、Auto 模式误用内置模型及配置导入。先完成至少两个家族各一条真实客户端闭环，其余组合并行推进。
