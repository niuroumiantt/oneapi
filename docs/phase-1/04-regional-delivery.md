# 阿里云、AWS 与共享发布

版本 0.2，2026-11-06。用户已确定：中国区阿里云、海外区 AWS，使用不同域名，共用核心设计和业务代码。具体域名、AWS 地理区域及收款法人仍待配置。本轮没有创建云资源、域名或部署工作流。

## 分开域名与数据，统一开发

| 项目 | 中国区 | 海外区 |
| --- | --- | --- |
| 云环境 | 阿里云中国大陆所选地域 | AWS 经批准的境外地域 |
| 域名 | 独立中国区正式域名及 API 子域名 | 独立海外正式域名及 API 子域名 |
| 身份 | 本区身份库、Cookie、回调地址和 Provider 应用 | 本区身份库、Cookie、回调地址和 Provider 应用 |
| 登录显示 | 微信优先，可靠恢复入口，GitHub 可选 | Google/GitHub 优先，X 可选，可靠恢复入口 |
| 支付 | 微信支付、支付宝，人民币业务账户 | 合格 Stripe 商户等，首期美元业务账户 |
| 数据 | 本区数据库、对象、队列、日志、备份、Key | 本区独立数据库、对象、队列、日志、备份、Key |
| 商品与政策 | 本区获准供应路径、价格、促销、条款 | 本区独立获准供应路径、价格、促销、条款 |

同一代码仓库保持一条主开发线；不长期维护一套中国代码和另一套海外代码。共用身份流程、组织/项目、模型目录结构、接入模板、订单、账本、促销引擎与 UI；区域差异进入配置和少量有明确接口的适配器。

建议配置包括 region、public_origin、api_origin、legal_entity_id、currency、enabled_identity_providers、payment_adapters、approved_offer_policy、legal_document_versions、support_contacts。密钥只在地区秘密管理设施中引用，不进入仓库或客户端可读配置。

## 域名和注册准备是并行工作

阿里云官方说明，中国大陆服务器承载的网站需要按要求完成域名 ICP 备案，审核涉及主体、网站和接入信息；其他经营许可/行业要求仍按实际服务判断。[DEP-01](06-sources.md#deployment)

OAuth 回调、微信网页/支付域名、支付宝异步通知、Stripe webhook、API CORS 和 TLS 证书都与最终域名关联。域名尚未定时用明确的测试域名配置，不能把演示域名当成已经注册。

网站语言只影响文案。地区由经过验证的部署配置和域名映射决定，不能信任浏览器上传的 region 参数来选择商户或账本。跨地区入口给出明确跳转说明，原始账号资料、资金和请求数据不默认复制。

## 自动更新的目标实现

共享功能提交到 main → 自动检查/有意义的测试 → 生成带 commit SHA 和摘要的不可变发布产物 → 两区测试部署 → 两区各自健康与业务冒烟验证 → 在该区发布条件满足后自动滚动更新或小流量发布。

同一应用产物可以复制到两区镜像仓库并核对摘要，避免中国区运行时依赖跨境拉取源代码或镜像。地区配置独立注入；若前端构建确实含地区常量，则由同一提交构建有可追溯清单的地区产物，不声称其二进制完全一致。

生产机器拉取指定发布产物。发布记录保存代码提交、产物摘要、配置版本、条款版本和数据迁移版本，避免使用含义会变化的 latest 作为唯一依据。两区可以使用同一版本，但升级成功/失败和回滚分别记录。

GitHub Actions 可以用 environments 分开部署约束与秘密，OIDC 可与支持的云身份体系交换短期凭据。具体阿里云/AWS 角色和信任策略在实施时验证，限制仓库、分支/环境和权限。[DEP-02](06-sources.md#deployment)[DEP-03](06-sources.md#deployment)

## 小范围地区更新如何管理

条款、商户、支付能力、可售模型、活动、备案展示、客服等以地区化且有版本的配置发布。依然保留变更人、审批或操作权限、生效时间和回退记录，不在服务器上手改未追踪代码。

财务规则、权限隔离和接口协议这样的共享业务逻辑，经同一代码评审与测试进入主线。某地区紧急修复可以独立发布经验证的提交；修复必须回到共同主线，防止永久分叉。

数据迁移采用向前兼容的扩展/收缩步骤，应用回滚不依赖强行回滚已写入的数据结构。一个地区未能升级时，共享版本至少覆盖约定的新旧接口兼容窗口。

## 不能用服务器地点替代完整数据路径

客户所用 Agent/IDE 也属于实际路径。若客户端通过自己的云端构建提示或转发请求，产品需要披露并按客户场景评估；中国入口在阿里云并不能保证 Cursor 等客户端链路完全留在中国。不同地区获准的客户端/模型组合可不同。

全球运营看板先使用必要聚合数据。客户原始提示词、凭据、完整身份资料和支付数据不自动汇集到一个全球后台。两区支持人员的权限和实际访问也纳入区域范围。

## 首期部署验收

两区登录回调互不接受、Cookie 不跨域共享、Key 绑定地区、支付订单不能换商户或币种、跨区码有明确反馈、数据/备份独立、同一版本两区可发布、单区可回滚、生产秘密不在浏览器包与仓库中、未批准供应路径不可被 fallback 使用。
