主体名称和域名由用户提供；后续已核实新域名解析并完成阿里云独立预览部署，未更改 DNS；备案/商户资格不因静态站可访问而视为完成核验。微信/支付宝商户和 DeepSeek/智谱采购账户是否开通仍待核实。海外主体及域名尚待确定。

## 一个域名下的入口建议

| 路径 | 用途 | 身份域 |
| --- | --- | --- |
| `/`、`/models` | 官网与模型广场 | 匿名可浏览 |
| `/login`、`/console` | 客户登录及个人/企业工作区 | 客户会话 |
| `/admin/login`、`/admin` | 员工登录及运营后台 | 员工会话 |
| `/api/customer/v1/*` | 客户业务操作 | 客户身份与资源权限 |
| `/api/staff/v1/*` | 员工业务操作 | 员工身份、地区/岗位范围 |
| `/v1/*` | 已验证的模型兼容 API | 项目 API Key |

入口域名均以 `https://oneapi.glocalstorage.cn` 为部署目标，路径是待实现契约。路径不同不构成浏览器安全隔离：不同身份使用独立 OAuth 客户端/受众与会话，服务端拒绝错域凭证；Cookie、CSRF、CSP、退出和会话撤销须整体验证。同源应用仍共享浏览器信任边界；后续若拆独立员工域名，应同步迁移回调、Cookie 和访问策略。

## 1. 员工、客户登录与权限

账号身份分为 `customer`（客户）与 `staff`（员工），与组织成员权限分开建模。公众注册创建 customer，不赋予员工权限。

客户在某个组织中的成员角色建议为 owner（组织所有者）、organization_admin、developer、billing、viewer；owner 只在该组织范围有效，不是“客户”的英文名称，也不代表平台所有者。客户创建自己的工作区时可获得该工作区的 owner 权限；受邀加入已有组织时仅获得邀请指定的权限，不能默认成为 owner。同一客户在不同组织可具有不同角色。

员工岗位角色建议为 identity_admin、supplier_operator、validator、operations、finance、promotion_operator、support、auditor。角色是权限集合，实际授权还依赖地区、组织、项目、资源归属和操作状态；禁止仅凭前端角色字符串放行。

| 操作 | 客户授权建议 | 员工授权建议 |
| --- | --- | --- |
| 项目与 Key | owner/组织管理员，或获授权项目开发者 | 客服只看掩码和必要诊断；无读取完整客户 Key 的入口 |
| 团队邀请/角色修改 | owner/获准组织管理员；所有权转移单独处理 | 身份管理员管理员工入离职，不能借客户注册授予员工身份 |
| 充值/账单/优惠确认 | owner/billing；开发者仅按权限查看本项目消费 | 财务查订单、核对、发起退款；不直接编辑账本余额 |
| 供应档案与报价 | 无 | 供应运营建草稿，验证人员记录结果，生产启用按授权审批 |
| 凭据与运行通道 | 无 | 服务端秘密引用；运维受控轮换/停用，普通后台不回显原始凭据 |
| 促销活动/佣金 | 客户领取允许的活动；推广员只见本人收益 | 活动运营拟定，具有独立权限者审核；财务处理结算 |
| 客服访问 | 用户自己的数据 | 受限支持视图；不默认接管账户或读取请求正文 |
| 审计 | 自己获授权的活动记录 | 审计只读；普通管理员不可删除已入账/已审计历史 |

员工采用邀请/管理员开通、MFA、岗位授权、离职撤权；公众注册只产生客户身份。人员少时可兼岗，但敏感审批不得借角色切换实现同人自审；需要独立复核的业务在人员条件落实后启用。

关键验收：跨组织读写/导出拒绝；客户会话进入员工 API 拒绝；错地区或错受众凭证拒绝；员工停用后现有会话失效；邀请过期及重放拒绝；绑定另一登录渠道不丢账户或重复优惠；登录与支付回跳恢复原选择。

认证协议、MFA 和会话尽量复用成熟身份系统，业务授权由本平台负责。Keycloak 等仍属候选，先验证中国微信接入、恢复与地区部署成本，再锁定版本，不先写一套自制认证协议。默认拒绝和逐请求资源检查符合 [OWASP 授权指南](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)；[Keycloak OIDC 文档](https://www.keycloak.org/securing-apps/oidc-layers)说明其标准身份端点，但不代表已完成本项目集成。

## 2. 供应商管理与产品验证

保留 Supplier → Contract/Account → SupplierModelOffer → Endpoint/CapacityPool 的关联。商业准入、技术验证、生产启用分别记录；测试成功不自动得到销售授权，也不自动上线。

验证以“地区 + 采购产品/真实版本 + 端点配置版本 + 协议 + 客户端版本/模式 + 适配器版本”为证据范围。包括：鉴权/连通、文本与流式完整性、工具往返循环、相应多模态能力、用量维度、费用核对、并发与限流、断线/超时/恢复、凭据轮换及数据路径。首期先完成两家族各一条真实获准路径。

测试结果保存样例版本、时间、执行者、有效/失败项、错误、用量与成本证据；默认不保存客户提示词，也不把原始凭据写入测试报告。测试请求走独立预算和平台成本中心。

型号/端点/协议/适配器变化使相关技术证据重新待验；纯价格变化先重审经济条件，不无差别重跑全部技术验证。授权到期、凭据失效、资金不足、容量紧张、健康降级分别处理。

后台建设供应档案、产品、验证任务/报告、采购账户与资源、运行通道、事故和对账。产品从草稿到测试、待审核、可生产、暂停/退役的变化均有原因和记录。运行时仍逐次校验资格、资金和容量；缓存的已批准标签不是永久通行证。

## 3. 模型广场与产品设计

沿用两家族入口与“接入我的工具”。前台模型商品和后台采购产品分离，同一模型的多个供应商不复制成多个同名卡片。公开商品显示地区、能力、准确价格维度和已验证的客户端组合。

目录结构、商品定价、客户端兼容、界面呈现分别维护。原型中的 DeepSeek Chat/Reasoning、GLM Coding/Vision、价格和质量均是演示，不作为正式型号目录导入。

客户路径：选模型/工具 → 登录并选工作区 → 核对价格/权益/项目 → 生成受限 Key 与配置 → 客户端实际调用 → 查看费用和状态。仅平台连通或单次文本成功不能标为工具循环通过。

供应停售影响新售卖/新激活；已有 Key 不无故删除，按已承诺服务及当前可用性处理。无获准备援时明确错误，不默默跨区或改用不同模型。正式商品上线需要可追踪的供应、价格和验证证据。

## 4. 付费、调用与退款

以预付使用为首期默认建议，企业工作区同样可预付。订单、现金/赠送权益、消费费用、采购成本和佣金各有独立记录，PostgreSQL 业务账本是金额关系的权威来源。

充值：创建固定商户/账户/金额/币种订单 → 当地支付 → 后端验签和查单 → 持久接收事件 → 唯一业务操作入账 → 账户可用。前端跳回不加钱。回调先可靠持久化再响应，后续任务可重试；事件 ID 与订单经济动作双层去重，旧事件不能覆盖新事实。Stripe 明确存在重复和乱序事件，见 [官方 webhook 文档](https://docs.stripe.com/webhooks)。

调用：权限与资格 → 冻结价格/权益 → 原子检查账户和项目限额并预占 → 上游实际尝试 → 按可靠 usage 结算 → 释放余量。只有具备可执行消费边界的模型/请求进入预付路径；未知计量进待核对状态，不能伪造实报或因任务超时盲目释放仍在执行的预占。

记录每次上游尝试与采购成本，客户账单按公布规则结算。重复处理费用事件不重复扣费；多次实际推理不声称天然只执行一次。内部金额用明确精度的 decimal/整数单位，展示与支付精度分别处理。

退款先锁定可退实付来源并协调在途预占，外部退款确认后冲正；客户退款不抹掉已发生采购成本。商户对账、差额处理、退款客服与发票申请路径必须可执行。

## 5. 促销、归因与佣金

保留活动、促销码、兑换、价格权益、佣金规则五类对象。所有已启用登录方式和符合条件的新老客户适用；登录前只保存意图，登录后绑定选定计费账户。

建议消费单价优惠、单层佣金、活动不默认叠加。企业由 owner/billing 确认，普通成员不能擅改整个公司的价格与归因。九折与六折按同一参考基准比较，实际折扣和返佣比例尚待确定。

本地区计费账户 + 活动 + 权益批次用于领取防重；每笔费用保存使用的权益/价格/计佣版本。活动停用先阻止新领取，既有权益按领取时规则处理。优惠预算也需预占和并发保护。

佣金建议来自已收款、实际消费且符合规则的净服务金额；充值本身不立即变成可付佣金。待观察 → 可结算 → 审批 → 已付，退款/拒付另外冲回。退未消费本金不自动冲掉已完成合格消费的佣金。

活动发布前检查供应成本、费用、佣金、预算和预计容量，不能承诺已经不可交付的优惠。推广员只看本人必要转化和收益；客户 Key、请求内容和其他推广员客户信息不进入推广视图。

| 公开注册发布 | 中国域名、已启用登录/支付、监控/支持、发布回滚 | 下列发布证据就绪后面向公众开放，不要求邀请 |

公开注册上线证据：

1. DNS/证书/阿里云部署、主体与域名所需手续、实际商户资格核实；回调和条款显示正确主体。
2. 至少可用的本区登录与账户恢复；启用渠道分别验收，未接通渠道不伪装可用。注册/登录限速、滥用处理和员工 MFA 就绪。
3. 两家族各一项可交付商品，实际版本/使用范围/价表/限额已核实；支持的工具组合有测试记录。
4. 微信/支付宝拟上线的支付产品完成真实闭环与退款核对；境外支付与资料在相应区域单独验证。
5. 余额不足并发、重复/乱序支付、请求失败/流中断、退款竞争、重复兑换、佣金冲回及越权访问测试通过。
6. 公开注册不自动发放无限试用；首次充值、单账户日消费、并发、活动总预算和新商品开放量按实际运营策略设定并说明。
7. 备份恢复、关键告警、回滚、客服、退款/发票与供应事故责任人落实；生产页面移除演示标记并且只读取真实业务数据。

公开注册是用户已确认的开放方式；具体消费限额、活动比例和日期仍待实际成本及容量证据确定。内部验收/发布演练不应被写成邀请制经营决策。
