# 身份与工作空间的边界

客户使用同一个邮箱账号，可以拥有个人空间，也可以加入一个或多个企业空间。登录只确认“是谁”；进入空间时，再确认“代表谁、能做什么”。企业代表人与企业员工的权限按企业分别计算，不能因个人身份或其他企业的权限自动继承。

| 空间 | 当前页面识别 | 可以承载的操作 | 视觉方向 |
| --- | --- | --- | --- |
| 个人空间 | 个人身份 | 个人模型发现、项目及账户安全 | 暖白底、海军蓝文字、品牌红色操作 |
| 企业空间 | 企业名称及当前企业角色 | 团队、员工权限、采购、预算与用量 | 冷蓝底、深蓝侧栏、蓝色操作 |
| 平台内部 | 公司员工岗位 | 客服、供应、运营和经授权的业务后台管理 | 石墨灰底、独立员工身份 |

客户在个人与企业空间之间切换时，页眉始终显示当前空间、企业名称和角色。未来下单、创建 API Key、分配额度等操作，必须明确绑定当前空间和企业 ID；从公开模型广场进入采购流程时，需要再次确认购买主体。切换空间不能通过只改前端颜色或路由完成授权，所有数据请求仍由服务端按会话、企业成员关系和岗位检查。

平台 `platform_admin` 是 oneapi 应用的最高业务后台岗位，不是服务器 root、数据库管理员或部署凭据。现有内部台由公司身份中心和应用岗位双重校验，当前经公网域名进入；公开导航不展示员工入口。目标是把客服、运营、供应和只读统计保留为可远程访问的最小岗位，而部署、密钥、数据库和身份根配置只经独立受限的运维通道执行。后续如迁到内部域名或 VPN，仍需保留身份验证、MFA、岗位检查及审计，不能把“知道内部网址”当作权限。

当前企业资金、Token 用量和付款尚未接入真实账本，页面只能显示“待开放”。视觉分区不改变这些业务状态。
