# 客户实际购买什么：产品契约讨论稿

状态：产品主线已由用户确认，2026-11-07；具体供应授权、型号、价格、退款条款和支付接入仍待核验。本文不是已发布的商品或价格。完整供给到交付链路见 [供应到客户的产品蓝图](17-supply-to-customer-blueprint.md)。

## 建议的第一种交付产品

semifly.ai 向个人和企业交付 **按实际调用计费的模型 API 服务**：客户在自己的计费空间充值人民币余额，选择已获准的模型，创建限定模型、项目和额度的平台 API Key；每次调用按照公开的该型号价格扣费，看到用量、费用和失败状态。企业代表人购买和分配预算，员工在获授权的模型与预算内使用。

客户购买的是 semifly.ai 提供的 API 服务与可消费余额，不是上游供应商账号、机器租赁、某个 Agent 软件订阅，也不应把 Token 数量直接等同人民币余额。输入、输出、缓存等 Token 只是计量维度。首期不把“充值 ¥1000”说成“购买 1000 元 Token”，也不把每次充值绑定到一个型号；型号价格可以不同，余额按实际费用扣减。

## 客户看到的三层目录

| 层级 | 客户看到什么 | 平台记录什么 |
| --- | --- | --- |
| 品牌/家族 | DeepSeek、智谱 GLM 等品牌入口 | 品牌归属、地区与展示顺序 |
| 具体型号 | 例如一个已核验的精确型号、用途、能力、状态 | API model ID、能力与协议版本、验证证据 |
| 可售服务 | 本区价格、计费维度、服务状态、可用工具和限制 | 商品版本、价格版本、获准供应路径、发布审批 |

同一品牌可能有多个型号；同一型号可能有多个上游供应路径。客户先按品牌找到具体型号，平台在后台选择已验收的供应路径。未取得授权、未完成真实测试或未审核价格的型号只能展示为“待开放/目录预览”，不能显示购买、生成可用 Key 或伪造可用率。

## 首页和工作台流程

1. **模型广场**：先看品牌，再看型号卡片。卡片显示适合的任务、区域、输入/输出价格、验证与可用状态；详情可看协议、限制和价格说明。
2. **开始使用**：选型号和项目。个人进入个人钱包；企业成员进入企业工作空间，代表人可充值和授权。
3. **充值**：计费账户选择金额、确认支付；经真实支付回调确认后入账。订单是余额充值订单，型号选择作为后续接入意图保存，不决定这笔余额只能用在一个型号。
4. **授权与接入**：在已获准型号范围内创建平台 Key，配置项目/员工限额。显示一次完整 Key 与客户端接入步骤。
5. **调用和账单**：每笔请求记录型号、用量、有效单价、扣费、项目/员工、状态和追踪号；企业代表人可看汇总与成员明细。

促销按有效型号与消费费用生效，不直接伪装成充值本金。供应商采购、验收、成本与路由留在内部管理台；客户侧只展示真实服务承诺。

## 当前演示链路与需要改造的地方

`demo-chat`、`demo-code`、`demo-reason` 是三个匿名计费算例，不对应真实品牌、型号或价格。当前模拟订单要求选一个算例，模拟付款后仅可为该算例创建演示接入；这是验证账本和权限的脚手架，**不能直接升级为正式交易**。本轮页面将其明确标为计费演示，并提供品牌目录入口。

下一轮在用户确认产品契约后：将模拟订单改为与型号解耦的充值订单；在品牌/型号目录完成选择；演示接入按型号授权，保留个人/企业预算与用量演示。现有演示记录保留在隔离的 `demo_*` 表，不转成真实余额或真实调用历史。

## 已确认的商业主线与待定事项

1. 首售采用“共享人民币预付余额 + 按实际型号和用量扣费”；个人与企业计费账户分别记账。用户提出最低充值 ¥5、未用余额可退、原支付路径退款；退款手续费 15% 是待法务及支付渠道核验的提案，不能直接作为所有退款的固定规则发布。
2. 上游采购 Key 可提供多个型号；Key 的能力清单并不等于可售清单，型号仍须通过合同授权、实测和定价审核。首售的真实品牌与型号待供应资料和测试确定。
3. 企业代表人给员工分配人民币预算和可用型号；员工在授权范围内共用企业余额，成员间调配不产生第二份充值金额。
