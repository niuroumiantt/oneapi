# AutoKernel 候选供应商调查与引入方案

日期：2026-11-07。状态：公开资料初查、流程设计；**未确认合同主体、机器来源、API 服务、容量、价格或 SLA**。这份材料用于与供应商讨论和设计后台，不表示准入或可售。

初步判断：算子优化技术和机构背景是合作亮点，但**公开证据无法验证其“自有机器租赁并稳定提供 API”**。要先弄清楚报价到底是 GPU/算力租赁、托管推理服务，还是带上游转供的模型 API；不同类型的授权、计费、验收和故障责任不同。官网声称的融资也不是供给 SLA 的证据。

公开检索未发现足以确认行政处罚或司法风险的可靠一手材料；这不是“没有处罚/诉讼”的结论。签约前仍要用国家企业信用信息公示系统、中国执行信息公开网及正式尽调材料核对两个可能主体。

## 对供应商的核实清单

请由供应负责人索取以下脱敏或可签约材料，真实密钥只进入受控凭据系统，绝不放在备注、证据链接或邮件转述中。

1. **签约与开票主体**：营业执照、统一社会信用代码、收款账户户名、实际服务方与数据处理方；如不同于智子芯元，列出授权和责任链。核对官网域名、合同章、发票与收款主体。
2. **供给模式**：机器是自有、长期租赁、云商采购，还是别人的 API 转供；机房/云区域、硬件型号与数量、专享或共享、隔离和维护责任。提供可核验的订单/资产/租赁证明和容量范围，不要求公开商业秘密。
3. **模型服务权利**：每个实际模型、版本、许可证/商业授权，是否允许我方以 semifly.ai 服务客户、是否允许企业客户和再分配、地域及数据限制；若使用第三方上游，披露真实上游和转售许可。
4. **接口与服务承诺**：API 文档、协议差异、流式/工具调用/结构化输出支持、模型更新通知；合同 SLA 的可用性分母、排除项、故障等级、响应/修复时间、补偿、容量或并发上限及扩容规则。
5. **数据与财务**：提示词/输出是否留存、训练使用、日志位置与期限、删除和事件通知；采购单价、税/币种、最低消费、账期、退款、对账粒度、余额/usage 取数方式。

未取得前，AutoKernel 只能作为“候选供应商”；不要建立带可售暗示的模型商品、生产路由或预付大额采购。

## 供应商引入页面：从长表单改成有下一步的工作流

现有页面从“新增供应商档案”长弹窗开始，第一步混入主体、地区、来源、邮箱、官网和备注；然后产品表与 7 项资料核验散落在页面。改成在普通笔记本的一屏内可见的**候选卡与工作流**；仅详情和证据可进入二级页。

| 阶段 | 页面上显示的任务 | 完成门槛与按钮 |
| --- | --- | --- |
| 01 建档 | 品牌、合同主体、服务类型（官方 API / 授权转供 / 托管推理 / GPU 租赁 / 软件优化）、联系人、负责人 | 只需核心四项即可保存候选；官网等附加资料在详情补录。服务类型允许“待确认” |
| 02 商务与权利 | 合同主体核对、来源链、模型/数据权利、地区、报价、SLA、服务支持 | 逐项附证据、审查人、日期与有效期；有冲突标“待澄清”而非假装已通过 |
| 03 接口试用 | 测试账号/受控密钥引用、端点、模型版本、功能清单与自动测试记录 | 单独“运行验收”动作；资料 7/7 不自动等于技术通过 |
| 04 计量与压力 | 在代表性负载下测延迟/吞吐/并发、核对 usage 与供方账单 | 测试报告含负载、地区、时窗、样本量、原始请求 ID、异常及结论 |
| 05 小流量试运行 | 限额和预算、故障回退、值班联系人、观察窗口 | 只给内部/受控客户，设最大请求量和支出，事故可一键停用 |
| 06 发布与复评 | 商务、技术、安全、财务审批，明确可售型号/地区/价格版本 | 多方签核后才允许进入真实路由与客户目录；到期或版本变更触发复验 |

供应商总览每一行只显示：名称/主体、供给类型、阶段、已核证据、最近一次真实测试、风险标记、下一步与负责人。点开 AutoKernel 显示三个显眼的“待确认”：**合同主体是否相同、机器/接口究竟由谁提供、是否有向我方客户供给的权利**。现有 7 项资料核验可保留，但将 `source` 与 `sales_rights` 提升为首要闸门；“产品验证”必须新增独立技术试验记录，不把文档状态改名为性能结论。

## 产品验收：先声明要卖什么，再验证能否交付

测试对象不是“这家公司”笼统一项，而是 `法律主体 → 合同 → 采购账户 → 端点/容量池 → 模型版本 → 客户商品`。同一供应商有多个区域、机器池或型号时分别验收。每次变更模型版本、端点、底层算力或数据地区，关联验收失效或至少进入复核。

| 验收层 | 首批检查 | 证据 |
| --- | --- | --- |
| 合法可用 | 真实供给链、许可证、销售/再服务范围、数据地区、合同期限 | 经审批的合同/授权摘要与有效期 |
| 功能 | 鉴权、模型 ID、普通/流式完成、工具调用循环、JSON/结构化输出、上下文和错误码 | 固定测试集、请求/响应摘要、版本和运行环境 |
| 性能与容量 | 冷热请求、首有效 token 时延、完整时延、输出速度、并发阶梯、限流、长上下文 | 基线与负载曲线，注明 p50/p95/p99、样本量、窗口、输入/输出 token 分布 |
| 可靠性 | 连续探测和真实流量、流中断、超时、余额用尽、Key 失效、维护和故障回退 | 错误分类、事故/工单、恢复时间；不以单次 200 判稳定 |
| 计费 | 输入/输出及缓存口径、失败/重试计费、供方 usage 与账单 | 每次尝试成本、供应账单和差异项；对账不清不进入自动收费 |
| 数据 | 提示词/输出留存、跨区路径、模型训练使用、删除与安全事故通知 | DPA/服务条款及实际技术抽验 |

### 仪表盘的统计口径

- **客户结果**：端到端成功率；**供应端结果**：每个实际尝试的有效完成率。备用路由救回客户请求时，主端点失败仍计入供方质量。分母明确排除客户主动取消、参数错误等非供方原因，并独立展示这些量。
- **实时观察**：过去 15 分钟、24 小时、7 天的请求量、样本量、错误分类、TTFT p50/p95、完整耗时 p95、输出速度 p50/p10、429、并发占用和最后成功时间。数据不足/过期显示“未知”，不显示虚假的 99.9%。
- **经济观察**：采购预估成本、供方确认成本、账单差异、失败重试成本、余额覆盖天数、容量利用率、合同/SLA 到期。按端点、实际模型版本、地区、采购账户和容量池下钻。
- **验证收获**：每次试验保存“目标、样本与负载、基线、结果、失败项、结论、复测时间”；与以前版本比较变化，形成可追溯的产品决策，而不是只有通过/不通过。

首轮建议运行一套固定功能集，再用脱敏但代表实际业务的短/长文本及工具请求做 24–72 小时受限试运行。通过条件应在合同和目标客户场景明确后设定；不能先写“99.94%”当成通用准入门槛。生产监控用被动真实流量 + 少量合成探测，探测费用由平台承担。

## 交易建议与风险位置

| 可见优势 | 对应限制/风险 | 首次合作的控制方式 |
| --- | --- | --- |
| 有算子优化与国产算力适配的公开案例，可能在特定芯片上形成成本/性能优势 | 模型适配成绩不等于持续运营 API、峰值容量或可用性 | 要求对我方指定模型、版本、地区、负载做独立验收 |
| 研究院关联和港交所投资公告为主体/研发背景提供独立线索 | 融资与研究背景不担保合同履行；研究院 2026-10 公示部分股权拟转让，控制关系应以签约时资料为准 | 核实当前股权/授权链、合同盖章、收款和开票主体 |
| 若确有机器与托管推理，可比纯转售方更直接掌握技术栈 | “自有机器、稳定 API”未见公开证据；还可能存在单机房、共享池或真实上游依赖 | 核验资产/租赁与机房、容量池、故障域、售卖权与备用方案 |
| 可谈专有容量和定制适配 | 早期公司交付与支持体系可能未成熟，预付与最低承诺风险较高 | 小额、短周期、分阶段验收付款；明确停服、退款、迁移与 SLA 补偿 |

建议首次合同附件明确：具体模型/版本和供给类型、实际服务与数据处理主体、我方客户使用权、区域、容量与限流、计量与账单、SLA 口径、价格生效/变更通知、P1 联系方式、故障补偿、退出与余额退款。先受限试点，验证数据达标再扩大采购及公开售卖。

## 与当前实现的差距和实施顺序

目前 `suppliers` 只有三类来源，未覆盖“GPU 租赁/托管推理/软件优化”；`supplier_offers` 只能存模型 ID、协议和地区；`supplier_offer_checks` 七项是人工资料状态；前端长弹窗在截图中超出一屏。下一步应先补**供应类型、候选阶段、联系人与证据元数据**，并拆成紧凑建档与详情页；再建**技术验收运行/结果**和**观测指标**表；最后连接真实凭据、路由、成本与审批。不能仅通过改前端文案把 7/7 视为售卖许可。

待用户/供方材料：实际签约主体、服务清单或报价、API 文档样例、SLA、模型与区域列表、机器归属及数据处理说明。收到后用这些资料把 AutoKernel 候选卡变成具体采购产品与有明确数字的验收标准。
