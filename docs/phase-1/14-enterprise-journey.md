# 企业工作空间第一版：两种身份与两条路径

2026-11-06 用户确认：企业侧只展示企业代表人、企业员工。代表人创建企业空间，负责邀请、成员管理与后续采购；受邀者统一成为员工。员工不在前台选择财务、部门管理员等岗位。旧数据库中已有的细分角色暂保留兼容读取，新邀请不可再授予它们；以后若需要代表人交接，单独设计受审计的交接流程。

## 代表人的工作顺序

1. 注册并验证邮箱，建立企业工作空间。第一版一个企业空间即一个团队，不创建含义重复的 team 层级。
2. 前往模型广场选模型。模型商品、价格与采购校验接通后，进入订单。
3. 付款确认、企业钱包入账后，才能分配可用额度。余额、预占、结算和退款以服务端账本为准。
4. 在管理台生成一个七天有效的共享邀请链接，可发给一人或多人。申请逐人审批。批准后的成员默认零预算、零模型权限；后续由代表人单独分配额度与模型。费用与 Token 卡片只显示真实数据或明确的开放状态。

## 受邀员工的工作顺序

代表人生成共享链接并自行发送。接收者可用任意邮箱注册或登录；新账号必须先完成邮箱验证。接收者提交加入申请时尚未获得企业成员身份，代表人在管理台逐人批准或拒绝。批准后统一成为企业员工，默认零预算、零模型访问权限和零 API Key，必须再由代表人安排可用范围。已注册的个人账号使用同一登录身份申请，不复制账户和个人资金。链接可重复使用，代表人可撤销；过期后可生成新链接。旧的逐邮箱开通接口已退役，旧链接失效，历史记录保留在数据库中供审计与后续保留期处理。

## 个人与企业边界

同一邮箱可以拥有一个登录身份和不同工作空间。个人空间与企业空间在数据、Key、资金、授权、账单和审计上分离；切换工作空间只改变当前上下文，不搬移资源。邀请员工完成入职后默认进入企业空间。个人入口保留在头像菜单，但不在受邀流程中抢主位置。现阶段不做个人数据合并到企业，也不把个人资金转入企业。

公司员工管理台属于另一身份域，仅通过公司身份中心与岗位授权进入，不能由客户企业角色获得。
