# 决定记录与待确认事项

当前版本 0.4；首期以 [并行工作线与验收](phase-1/00-priorities.md) 为准。

## 已确认需求

R01　同一产品面向中国和美国；先中国市场开始。

R02　首批模型家族为 DeepSeek 与 GLM。

R03　个人、企业、供应商、推广员、代理商、分销商、区域总代理和员工具有不同业务逻辑。

R04　企业支持采购、PO、账单与发票；个人支持个人付费。

R05　推荐码可以关联优惠和返佣，客户和员工都有控制台。

R06　代码有明确用途，命名清楚，成熟能力优先复用。

R07　前台偏苹果式简洁并增加色彩，后台高密度高效率。

R08　以 niuroumiantt/oneapi 为本次项目仓库。

R09　优先落实登录与身份、模型广场/Agent 接入、地区支付、线下促销码/返佣、供应商与供应产品五条工作线，允许并行开发；第五条由 R14 补充。

R10　中国区使用阿里云，海外区使用 AWS，各有独立域名；核心代码和绝大多数模块共用，两区工程同时开始。

R11　客户可先选模型或先选 Agent，再自然生成配套接入配置；重点研究 Cursor、TRAE（用户语音 trail 暂按此理解）、Qoder、WorkBuddy。

R12　促销码适用于符合活动规则的新老客户及所有启用登录方式；登录前输入的码和模型/Agent 选择在授权返回后保留。

R13　客户折扣与推广人佣金同时进入首期，具体数值尚未确定；九折/六折只是用户举例，按同一参考基准解释。

R14　供应商管理为首期重要主线：获取不同上游 API、管理供应商和供应产品、采购价格/计费、用量/需求/容量、质量、断线与持续稳定服务。

R15　2026-11-06 已看过实际原型并确认按珍珠白与蓝青紫风格推进，高密度后台沿用截图方向。

R16　本轮重点依次为员工/客户内外登录与权限、供应商管理与产品验证、模型广场与产品设计、付费、促销；先深化再上线。

R17　首轮直接开放公众注册，不采用邀请制作为正式开放前提。

R18　中国经营主体为深圳市格洛可半导体有限公司；先用 api.glocalstorage.cn。域名及主体由用户提供，基础设施和商户资格尚待核验。

R19　提取本视觉风格，供另一个对话改造 glocal dmg；保持该目标产品的品牌、业务和技术栈。

## 建议的架构决定

| 编号 | 建议 | 原因 | 状态 |
| --- | --- | --- | --- |
| ADR01 | 首期由平台统一销售获授权服务 | 明确交易、售后与开票责任 | 建议，待主体和合同确认 |
| ADR02 | 共用代码，独立域名与地区数据面 | 提高复用并控制跨境复杂度 | 用户确认方向：阿里云 / AWS |
| ADR03 | 模块化业务服务与独立网关 | 保持边界，减少过早微服务化 | 建议 |
| ADR04 | LiteLLM OSS 为网关候选 | 复用协议层，自有商业系统 | 待 M0 实测与许可证审核 |
| ADR05 | 不可变主账本与预占结算 | 保证金额可解释、可对账、可恢复 | 建议 |
| ADR06 | 单层推荐先行，多层渠道后置 | 保留商业扩展，降低首期争议与合规复杂度 | 建议 |
| ADR07 | 珍珠白与光谱色设计系统 | 满足精致前台与高效率后台 | 用户已确认方向；具体组件实现及可读性继续验证 |
| ADR08 | 采购账户/产品/容量池/价表分别建模 | 避免多 Key 虚增容量，支持不同费用和权益规则 | 0.3 设计建议，真实采购条款待核验 |
| ADR09 | 商业资格、凭据、资金、容量和健康分别管理 | 不让一次断线等同撤销合同，也不让探测成功绕过授权 | 0.3 设计建议，阈值待试运营确定 |

## 首批要决定的事项

| 事项 | 当前建议 | 为什么影响下一步 |
| --- | --- | --- |
| 首批客户 | 个人开发者和小型企业先行 | 决定服务承诺、客服与采购流程优先级 |
| 中国经营主体 | 已定：深圳市格洛可半导体有限公司 | 支付商户、开票与域名相关手续状态待核验 |
| 上游采购 | 官方标准 API 或有充分授权的服务商 | 决定毛利、数据路径、下级分销权限 |
| 首批供应产品 | 两家族各至少一项获准采购方案，核实价表/限额/账单 | 真实采购证据是模型接入、计费和促销联调的输入 |
| 供给与质量目标 | 按试运营需求核实容量、故障依赖及恢复规则 | 不能将公开限额或单次探测当作平台 SLA |
| 美国供应路径 | 单独审核实际供应商、法人和处理地点 | 不能仅复制中国端点 |
| 品牌与域名 | 中国首发 api.glocalstorage.cn；海外域名和最终品牌待定 | 核实 DNS/证书、OAuth 回调及支付配置 |
| 首发开放 | 已定：直接公众注册 | 完成真实验收并配置注册、消费与容量限制；不改成邀请制 |
| 价格与优惠 | 区域公开价与促销专属消费单价 | 折扣基准、期限、模型范围、上限及已有合同价关系待确定 |
| 返佣 | 合格已收款消费的单层佣金 | 比例、期限、观察期和上限尚未确定 |
| 企业账期 | 预付默认，信用审批后开启 | 控制坏账和采购系统复杂度 |
| 退款规则 | 来源追踪、原路退款和明确服务争议流程 | 须结合商户、合同、税务与消费者规则 |
| 开发资源 | 约 6–8 人核心能力为讨论基线 | 决定并行度与工期 |

这些问题不阻止形成第一版设计。进入相应生产环节前再逐项落实，不要求用户现在一次回答全部。
