## 五条工作线同时推进

A 登录与身份，B 两家族模型广场与 Agent 接入，C 中国/海外支付及计费，D 线下促销码与返佣，E 供应商与供应产品管理。共同底座为阿里云/AWS 独立域名环境、共享代码与接口、发布、秘密管理和基本审计。

| 里程碑 | 交付证据 |
| --- | --- |
| M0 | 共享数据/接口确定，首批采购授权、价表和容量核实，身份支付条件及客户端协议验证 |
| M1 | 五条线页面可操作，客户选择可恢复，供应产品/资源/质量可管理，模拟数据明确标识 |
| M2 | 真实付款、模型调用、用量、折扣、佣金、退款及采购账单核对完成 |
| M3 | 各地区分别通过上线条件，小流量开放、供应补充、故障恢复、对账与回滚验证 |

两区工程从第一轮同时建设。商业开放日期可以不同，不把美国区全部工程推迟到中国区之后。完整 PO/账期、多层分销、供应商自助入驻、全面 HR 和高级 BI 后续讨论；首期保留企业工作区、预付、必要开票和售后。

## 上线必须验证的场景

| 场景 | 验收结果 |
| --- | --- |
| 同一支付通知重复到达 | 一笔真实支付只产生一次应有入账 |
| 支付与退款通知乱序 | 通过状态和主动查询恢复，不覆盖新状态 |
| 余额不足时大量并发请求 | 预占总额不超过可支配预算或明确授信 |
| 用户退款与在途调用并发 | 可退来源正确，不能同时退款和继续占用同一资金 |
| 流式断连或缺少 usage | 进入可追踪状态，费用可核对，不捏造计量 |
| 网关成功后进程崩溃 | 使用证据可恢复，未决请求有补偿处理 |
| 上游重试或用户重试 | 尝试与逻辑请求区分，客户计费符合公布规则 |
| 价格更新与跨日请求 | 使用正确生效版本，历史费用不被改写 |
| 缓存与推理 token | 按上游含义计价，没有重计 |
| 合同价与推荐折扣重叠 | 按版本化优先级处理，不意外重复优惠 |
| 退款发生在佣金支付后 | 生成冲回及追回/抵扣记录 |
| 企业提交 PO | 经过授权和授信流程，不直接视为已付款 |
| 分销商分配子额度 | 总授权不重复创造现金或信用 |
| 其他组织请求对象标识 | 后端拒绝跨租户访问与数据导出 |
| 员工离职或 Key 吊销 | 会话和调用权限在约定传播期限内撤销 |
| 美国通道不可用 | 不自动回落到未经批准的中国路径 |
| 数据库恢复 | 可证明恢复后账本和请求关联仍一致 |
| 多 Key 共用账户或底层供给 | 容量按真实作用域汇总，不能虚增备用能力 |
| 欠费、限流、平台过载与凭据失效 | 按供应商业务码及阶段分类，分别采购告警、排队、熔断或轮换 |
| 单端点故障或授权到期 | 不误停其他正常产品；探测成功不恢复已过期商业授权 |
| HTTP 200 后流中断或只有心跳 | 不计为完整成功，未决费用可追踪 |
| 采购价格、资源包或合同变化 | 正确使用版本与有效权益，不重算历史客户费用 |
| 重复导入上游账单 | 不重复记成本/应付，汇总差异有明确责任人 |
| 发布大幅折扣活动 | 能检查采购贡献、资源到期与容量缺口，不预支未实现采购返利 |

## 服务与经营指标

分别设定平台自身与上游端到端指标。设计目标可从平台可用性 99.9% 起讨论，但必须注明测量边界、维护窗口和依赖，压测和试运营通过后才写成对外 SLA。

关注每百万 token 的实际贡献毛利、供应商成本偏差、已收款消费、退款拒付率、待核对费用、渠道获客成本、真实留存、请求成功率、p95 首 token 时延和工单解决时间。充值总额、注册数和调用次数不能单独证明业务健康。

容量规划按峰值并发、平均输出长度、流式连接数和账本写入量测量，不凭预设“百万用户”直接设计大型微服务集群。备份目标和恢复目标在首批客户承诺前确定并验证。

## 人员与周期

截图中的完整团队更适合多地区、规模化经营。首期可从约 6–8 名核心人员讨论：产品负责人/产品经理、技术负责人、前端、后端计费与集成、网关/平台能力、测试；设计、运维、安全、法律和税务按工作量采用专职或顾问。岗位可兼任，职责和审核独立性不能省略。

工期按 M0 得到的实际客户端版本、供应凭据、登录/支付应用资格和团队资源再估算。前版串行时间表不作为当前承诺。各条工作线有独立负责人，统一接口和验收证据；外部审批与页面/业务开发并行。

## 当前交付边界

当前交付是设计基线、业务规则和视觉方向，尚未建设生产网站、接入真实付款或运行模型调用测试。下一阶段从 M0 的共享契约与最小真实路径验证开始，五条主线并行推进。供应商自助入驻后置不影响内部供应管理首期交付。
